# ADR-0085 — Long-form `document` artifacts author incrementally via a capped `create` → `append_artifact_section` shape; the tool description is the forcing function and the per-call cap is a backstop (SHIPPED — Gap 2, under the ADR-0075 artifact epic; live re-probe PASSED 2026-07-14)

**Decision.** Give `document` artifacts the same `create` → `append` shape that already bounds `pages`. Add a `system.append_artifact_section` tool with input `{ artifactId, markdown }` that concatenates its markdown onto the stored document body with a `\n\n` separator inside the same `SELECT … FOR UPDATE` transaction + post-commit poke that `append_artifact_page` uses, and refuses a non-`document` artifact with `wrong_kind` (mirror of the pages verb). `create_artifact(document)` keeps `markdown` **optional** so a short document still lands in one call. A single shared per-call cap — `ARTIFACT_SECTION_MAX_CHARS = 15_000` (~2,200 words, ~75s of generation ≈ under half the 180s stream ceiling; started at 12K, raised after the live re-probe — see below) — bounds **both** `createArtifactInput.markdown` and `appendArtifactSectionInput.markdown`; the **stored** total stays 500K (`artifactContentSchema` document markdown), so a long document is many capped sections accruing into one body. Overflow is a hard schema reject whose message points at `append_artifact_section` (truncating prose is worse than rejecting it). The `create_artifact` description's `document` branch is rewritten from "author the whole document here" to "author the opening section (~1,800 words) here, then continue with `append_artifact_section` — each section renders in the sidebar as produced," and the same tool serves cross-turn extension of an existing document. This is a tool-contract change, not a rulebook rule; no DB migration (the stored shape is unchanged).

**The mechanism, stated honestly.** A tool call's arguments are _generated as a stream_, and the 180s ceiling is an `AbortSignal.timeout` on that stream (the Gap 1 / #511 mechanism). So for a document large enough to actually time out, the abort fires **mid-argument-generation, before a complete tool call is emitted and validated** — the per-call cap never runs on the case it exists to fix. The **tool description is therefore the load-bearing forcing function**: it induces the model to _proactively_ author section-by-section so no single generation is oversized. The cap's realized job is narrower but real: (1) a hard ceiling on any single stored write, and (2) forcing the non-compliant-but-sub-timeout document (finishes generating under 180s yet exceeds 12K) to chunk, so behavior is uniform across sizes. This is why `document`'s asymmetry with `pages` was a _capability_ gap, not a steering gap: `pages`'s `create` structurally cannot carry page content and each page is a naturally bounded unit, so the model chunks by construction; a section is a discretionary unit, so the shape enables chunking but the description must _induce_ it. Acceptance is gated on a live re-probe of a document sized to time out as a one-shot proving the model chunks proactively — not on the cap. **Re-probe result (2026-07-14, Auto/Sonnet):** a ~9,000-word / 59,740-char Silk Road report authored as `create` + 8 `append_artifact_section` calls (every generation ≤73s, zero stream timeouts, clean render); the model announced the plan up front ("multiple sections appended one by one"). The 12K cap fired twice (`too_big`) into self-correcting reissues — proof it backstops, but it under-fit the "~1,800 words" guidance, so the cap was raised to 15K. Escalation to alt (d) not needed.

**Why.** Live probes (2026-07-14, Auto/Sonnet) showed `pages` already self-chunks unprompted — a 7-slide deck ran as 9 bounded generations (`create` + one `append_artifact_page` each, ≤7.1s) — while a ~3,300-word `document` ran as **one 118.1s generation** (66% of the ceiling), the whole 23,119-char body one-shot through `create_artifact` because `markdown` carried it all and there was no append verb. A slightly longer document times out, and the Gap 1 in-step retry just re-runs the same one-shot. `document` was the only authorable kind with no bounded path. Steering the `pages` descriptions (the tempting "make it build incrementally" fix) is a no-op against already-correct behavior; the durable fix is to make `document` bounded the same way `pages` is — a shape change plus a description that gives the model a unit. `append_artifact_section` is additive and row-locked, so it needs no `baseContentHash`, and it doubles as the safe cross-turn "extend this document" operation, sidestepping full-replacement for additive edits.

**Scope and residual risk.** v1 fixes the **authoring/create** path only. `update_artifact` full-replacement (cross-turn edits) keeps the 500K cap and remains a single re-emit that can still time out on a large document — mitigated only by Gap 1 retry + per-turn effort sizing (#478); mid-document _surgical_ edits stay deferred. Two similar append verbs (`_page` vs `_section`) could invite tool-selection confusion — mitigated because the `wrong_kind` guard makes a mis-pick a self-correcting reissue. Because sections concatenate verbatim and the sidebar re-renders the _accumulated_ markdown after each poke, the model must split at block boundaries and keep each section self-contained (closed code fences), or an intermediate render hits the ADR-0075 bare-fence `MarkdownRenderer` crash class — a description constraint. The cap was tuned 12K → 15K after the live re-probe (below).

**Alternatives.** (a) **Steer the `pages` descriptions toward incremental authoring** — rejected: `pages` already self-chunks; this perturbs working behavior and fixes nothing (the "A-trap"). (b) **Empty `create` (no markdown), all content through `append`** — an exact `pages` mirror; rejected because a 12K-capped optional `create` is itself already ≤~60s-bounded, so forcing an extra round-trip on every short document buys only symmetry. (c) **Rely on the description alone with no cap** — rejected: no hard bound on a single stored write, and no consistency for the non-compliant sub-timeout case. (d) **Mid-stream tool-argument-size abort** (inspect the streamed partial arg, abort + return a "chunk it" signal when it crosses the cap) — the only way to make the cap _truly_ forcing against timeouts; deferred as the escalation lever if the live probe shows the model one-shotting past the description. (e) **Server-side decomposition** (the boss emits an outline, the server fans sections out) — framed-future for truly huge documents or if the model proves unreliable at self-chunking. (f) **Effort-capping as the primary lever** — rejected: that trades depth for speed and addresses the single-dense-artifact _thinking_ overrun (#478), a different failure mode.
