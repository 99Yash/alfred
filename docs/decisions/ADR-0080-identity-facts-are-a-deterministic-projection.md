# ADR-0080 — Identity facts are a deterministic projection over the ADR-0067 observation log, not direct writes; aboutness-by-construction + "no grounding, no row" (DESIGNED — grilled 2026-06-29, see docs/plans/identity-facts-projection-v1.md)

**Decision.** Identity profile facts (`employer`, `job_title`, `team`, `manager`, `location`, profile URLs) become a **deterministic projection over the ADR-0067 `observations` log**; `user_facts` stays the **materialized read view** every consumer keeps reading, but is no longer the authority. This reverses, _for identity keys only_, the ADR-0079 model where the per-document extractor writes `user_facts` through `proposeFact`. The bug that forces it: on prod the boss resolved `employer="Weekday"` (a recruiter who emailed the user) and `employer="yourelasticdash.co"` (a contact's domain) — third-party companies attributed to the user, the extractor's own stored rationale literally saying _"the company **he** is associated with."_ ADR-0079's gate proves **authorship** (`From=user`) but not **aboutness** (the claim is _about_ the user), so a user-authored doc mentioning a third party still leaks. Six invariants: **(1) No grounding, no row** — the projection never materializes a value without a traceable grounding observation; absent evidence it emits **nothing** and consumers read `null` ("not recorded"). Unknown ≫ fabricated; a filled-profile UI is never a reason to guess. **(2) Aboutness by construction** — a value derives only from observations with `subjectIdentity={kind:"user"}`, so the entire third-party-subject class is excluded _structurally_, not heuristically. **(3) Deterministic core, LLM at the edges** — grounding rules, the domain classifier, the adjudication/currency reducer, and the cardinal gate are deterministic + unit-tested; the LLM only _proposes_ candidate observations. **(4) One writer, one authority model** — post-cutover the projection is the **sole writer** of identity keys; _all_ inputs including `/settings` edits and chat corrections enter as **observations** (`source=user`, rank 0), and user precedence is decided inside the projection, not via a second direct-write path. **(5) Pure replay** — no `now()` in projection decisions (use observation `occurredAt` + run metadata) so the ADR-0067 versioned projection converges on replay; single-active keys upsert to one active row, retiring the prior with `validUntil`/`supersedesId`. **(6) Evidence-only never promotes** — `mentioned_company="Weekday"` stays raw evidence, `interviewing_with="Stripe"` is _situational state_, neither becomes a profile fact. The model spans **three layers over one log**: identity profile (governed, current-active-with-history), situational state (time-bounded, decaying, multi-valued — `job_search_active`/`interviewing_with`/`shipping_velocity_high`/…), and briefing narrative adaptation (consumes the projections, invents no durable facts). A **hard guardrail** bars any situational `target_org` from promoting into `employer`. The corporate guarantee is a structural, non-poisonable input: on connect, emit `subject=user, kind=user_org_affiliation, source=google_account (NOT user and NOT a Gmail message), accountId, accountEmail, orgDomain, verifiedHostedDomain, domainClass, status` with a typed payload at the observation boundary; disconnect is represented as a later `status="disconnected"` observation in the same account/domain family — graded by a **domain classifier with four outcomes** (`consumer_email`→no signal, `corporate_domain`→strong/may auto-confirm, `ambiguous_domain`→needs corroboration, `service_or_role_account`→never). For full email-address classification, a custom domain is `corporate_domain` only when the provider verifies the hosted/workspace domain (Google `hd`); otherwise it is ambiguous, so personal custom domains cannot auto-ground employer. Projection rows carry `source.kind="projection"` as a **writer tag only**; authority comes from `meta.groundingTier`+`derivedFrom`, ranked `user_correction > user_profile_edit > directory_verified > corporate_affiliation > self_authored_profile/signature > corroborated_public/cold_start > weak_mentions`. `job_title`/`manager` need **stronger grounding than `employer`** — a corporate domain does not ground them (Directory / self-authored / explicit correction / corroborated first-party only). First slice (1a) is **employer-only**, cheapest-correct-first.

**Why.** The #331 purge removed the junk flood but also evicted the buried-correct `company=Oliv AI` and left a contaminated `employer` (a different confident-but-wrong value) — proving data cleanup treats the symptom. The disease is a pipeline that lets an LLM per-document read write a durable identity fact with no aboutness check, no use of the strongest signal the user owns (their own corporate email domain), and no temporal currency. The ADR-0067 observation substrate already models exactly the needed primitives — `subjectIdentity` (aboutness), `participants`/`recipientCount`/`List-Id` (full evidence), `OBSERVATION_SOURCE_RANK`, versioned replayable projections — but only feeds the social graph today; identity still flows through the legacy path. Bolting aboutness onto `fact-policy.ts` would build a second adjudicator ADR-0067 intends to delete (and grow the parallel-truth split between the observation log and `proposeFact`). The deterministic-core/LLM-edges split is the explicit architectural tenet: keep the core provably correct, let intelligence live at the edges (briefing tone, candidate extraction). "No grounding, no row" is the anti-hallucination contract Weekday violated — not a ranking bug but an ungrounded value being asserted at all.

**Alternatives.** (a) **Bolt aboutness + authority + currency onto the legacy `proposeFact` path (ADR-0079 expansion)** — rejected: permanent two-truth-model split, and rebuilds the adjudicator ADR-0067 already owns; ADR-0079 is kept only as a deny-brake for the keys still on the legacy path. (b) **Infer demographics (age, "too old/young to work") from cold-start to set tone** — rejected as creepy/brittle; replaced by evidence-based status primitives (`student/founder/employed/retired/job_seeking/career_transition/open_source_active/shipping_heavily`) with provenance + confidence. (c) **`source.kind="projection"` as the authority rank** — rejected: flattens a Directory-grounded employer and a flimsy footer-inferred one to one rank; authority must read `groundingTier`. (d) **User edits keep writing `user_facts` directly while the projection writes too** — rejected: backdoor writer / split precedence; corrections enter as `source=user` observations. (e) **Own email-domain → employer as a deterministic sole asserter** — refined, not taken raw: corporate-classified domain _may_ auto-confirm, but only as `user_org_affiliation` evidence with provider hosted-domain verification for full email addresses, and a `source=user` correction overrides it; free-mail/ambiguous/role domains do not assert. (f) **Delete legacy bad rows at cutover** — rejected: retire via migration semantics (`superseded`/`rejected` reason `identity_projection_cutover`) so Weekday leaves active reads but stays historically explainable. (g) **Fill the profile with a best guess when ungrounded** — rejected by invariant (1); `currentCompany=null` is a valid, required output.
