# ADR-0071 — Tools tell the truth about their capability, and correctness is enforced at the result boundary, not only the input schema (extends ADR-0053/0068; resolves #222; closes the issue-summary give-up)

**Decision.** A tool's _surface_ (name, description, schema) must honestly represent what its API can and cannot do, and the boss must **attempt the closest real capability or state its limit — never silently narrow a task nor bail to the user for something it can resolve.** Concretely: **(1) GitHub search covers what its endpoint covers.** `search_pull_requests` is implemented on GitHub's `/search/issues` (issues _and_ PRs); it is generalized to `github.search({ q, type: 'issue'|'pr'|'both', … })` with the validated structured surface and qualifier whitelist of ADR-0068 **extended to issue qualifiers** (`is:issue`, `label:`, `state:`); the `@me`→login server resolution is preserved (installation tokens aren't a user). **(2) Per-item detail is a typed fetch-by-number**, not a query: `github.get_pull_request` / `github.get_issue` (`owner`/`repo`/`number`) return what search structurally cannot — `additions`/`deletions`/`changed_files` for a PR (the #222 LOC need; the boss fans out over search hits and totals, capped + `log()`-ed on truncation) and body/comments for an issue. **(3) `drive.export_file` is an honest read-in tool**: its purpose (pull a Google-native file's _text_ into the agent's context to reason over) is stated, its `mimeType` is bounded to a text-export allowlist (single source in `@alfred/contracts`), and a binary `mimeType` is redirected with a teaching message — "_I read files in as text; producing a downloadable PDF/slides for you is a separate capability._" **(4) A boss operating rubric** (one structural principle, not exemplars): resolve parameters you can look up (connected account, default repo, dates) rather than asking; attempt the nearest real tool before declaring inability; if you genuinely cannot, say what you can't do and what you _can_; **and when a live Sheet/Doc already answers the ask, that is the deliverable — stop there, don't chase a binary export** (in `run_m78xa3ei2w4n` the boss had already built the PR Sheet, then poisoned itself reaching for a redundant PDF). **(5) Minimal grounding (F2):** the boss preamble carries the user's connected integration **identities** (e.g. GitHub login `99Yash`, primary repo) so it resolves instead of asking. **(6) The result-honesty primitive:** a tool must surface silent-failure classes at the _result_ layer — never a confident zero for a structural reason. For GitHub this is now **defense-in-depth behind ADR-0068's validator** (which already rejects invented qualifier _keys_ pre-network): it catches the residue the key-whitelist structurally cannot — a _valid_ qualifier with a value GitHub can't satisfy (the validator checks keys, not values), or an `incomplete_results` truncation. Its load-bearing home is ADR-0074's general tier, where calls can't be pre-validated at all.

**Why.** Three prod/dev failures, one root cause: a tool surface that lies, and a boss that gives up on the lie. (i) #222: asked for total LOC across PRs, the boss correctly degraded — search genuinely can't return diff stats — but it _silently dropped_ the requirement instead of stating it. (ii) The issue-summary turn (dev `c31d57c2`, **zero tool calls**): the boss's own reasoning shows it knew its tools, found the workaround (_"exploiting any relationship between issues and pull requests"_ — correct, `/search/issues` returns issues), realized the request was self-referential (_"my identity as 'Alfred'… self-referential"_), then **abandoned every path** — web search, the PR-search route, its own self-knowledge — and asked the user for the repo. The tool said "pull requests only" though it always could search issues; the boss didn't know it was GitHub-connected as a specific account. (iii) The class also covers result-honesty: a search that _succeeds_ with `total_count:0` for the wrong reason. The original `merged-by:@me` confident-zero (ADR-0068's motivating bug) is **already closed** by 0068's qualifier validator — it rejects an invented _key_ before the network call — so the live residue is narrower: a _valid_ qualifier key with a value GitHub can't satisfy (the validator checks keys, not values), plus the un-validatable general tier (ADR-0074). These are the _same class_ as the `export_file` misuse — **bad context about what an API is for / whether a call really answered the question** — which is also ADR-0053's boss-blindness. The fix is truth-in-surface + a resolve-or-state rubric, not a bolt-on `get_issue` (rejected by the owner as exemplar/prompt-patching, per the principles-over-exemplars posture).

**The shape.** GitHub search keeps ADR-0068's `superRefine` whitelist (today `GITHUB_PR_SEARCH_QUALIFIERS` in `contracts/src/github-search.ts`, generalized to span issue+PR qualifiers and to conditionalize the always-appended `is:pr` on `type`) and structured time windows. The boss re-trips the `author:`-in-`query` collision _every turn_ (it re-derives the query from scratch and never carries the lesson forward), wasting a call. Surface clarity alone is unlikely to fix that — the description is _already_ explicit ("never hand-write those qualifiers into `query`") and the validator already rejects, yet it re-trips; the robust lever (proposed in #213) is **sanitize-and-merge** — strip colliding `author:`/`is:`/`state:`/date qualifiers out of freeform `query` and fold them into the structured fields, turning a hard error + wasted retry into silent correctness — rather than reject-and-retry. `get_pull_request`/`get_issue` are plain `fetch` against `GET /repos/{o}/{r}/{pulls|issues}/{n}` with the existing installation-token credential resolver; `riskTier:'low'`. The text-export allowlist and the rubric line live in `@alfred/contracts`/the boss prompt base respectively; F2 identity injection extends the boss preamble's connected-catalog (ADR-0053) with the _binding_ (which account/repo), the minimal first brick of the #218 user-model. Behavioral evals (evalite, ADR-0055): the boss searches issues with a structured/whitelisted query, totals LOC via fan-out, and never answers a confident zero on an unrecognized qualifier.

**Maintenance policy (the schema-sourcing question).** Integration tool schemas are **hand-curated Zod sized to the surface the boss uses**, not generated — because the bug-prone layer (query-DSL semantics: GitHub search qualifiers, Gmail `q` operators) is **prose-documented and absent from any machine-readable spec** (OpenAPI/Discovery/GraphQL cover _endpoint shapes_, not DSLs), so there is nothing to generate it from. Drift on the curated set is caught by **cheap live-API evals**, not a codegen pipeline. Breadth ("do anything") is _not_ pursued by hand-modeling every endpoint — it comes from the general tier (ADR-0074). The two tiers share **one** correctness primitive: result-honesty (#6) — the half of correctness that scales to calls you cannot pre-validate.

**Alternatives.** (a) **Add a `get_issue` tool and a prompt bullet** — rejected: treats the symptom; the disease is the lying surface + premature give-up. (b) **Reverse ADR-0068 into a raw native-DSL pass-through** (the owner's first instinct) — rejected after re-reading 0068: it re-opens the confident-wrong-answer hole (silent zero on bad qualifiers) for marginal gain, since the whitelist already permits the _entire valid_ DSL and only blocks qualifiers GitHub doesn't have. Raw passthrough is the right _long-tail_ mechanism, but with result-honesty + risk controls — that's ADR-0074, not a reversal here. (c) **Generate schemas from OpenAPI/Discovery** — rejected now: heavy for ~15 tools, and it can't cover the DSL layer that actually broke; revisit only if the curated set grows large. (d) **Full identity/relationship modeling for F2** — deferred to #218; only the minimal connected-account binding ships here.

**Cross-ref.** Extends ADR-0053 (connected catalog → adds the _binding_) and ADR-0068 (keeps + extends the validated GitHub surface; does **not** reverse it). The honest read-tool half is the tool-level companion to ADR-0070's platform sanitizer. The result-honesty primitive is inherited by ADR-0074's general tier. First brick of the #218 user-model spine. The deferred produce-artifact capability is ADR-0075's epic.
