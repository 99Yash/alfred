# ADR-0073 — Sub-agent join via a child-completion wake signal, not scratch-polling (BUILT + reliability backstops PR #274; finalization invariant deferred — see amendment)


**Decision (designed, not yet built).** The boss waits on a spawned sub-agent by **parking on a wake-condition that the child fires when it reaches a terminal state**, replacing the current fire-and-forget + N-times-`read_scratch` + apologize. Reusing the existing `wakeCondition`/`signalRun` machinery (service.ts): **(1)** a new tool `system.await_sub_agent(childRunId)` sets `wakeCondition {kind:'signal', name:'sub_agent_done:<childRunId>'}` and parks the parent step as `waiting`; **(2)** when a child run commits to a terminal status (completed/failed/cancelled), the executor reads `metadata.parentRunId` and calls `signalRun(parent, 'sub_agent_done:<childRunId>')`, flipping it `runnable`; **(3)** `await_sub_agent` returns the child's real outcome — terminal `status` + `output` + `error` from `agent_runs` — so the boss reports the truth instead of inferring from a scratch key; **(4)** a defensive parent wait-ceiling; **(5)** a rubric line: never promise an out-of-turn notification — there is no async notify path, so either complete in-turn or fail honestly now.

**Why.** Dev-proven (#268): the boss spawned a child, polled `shared.pdf_file_id` 4× (`found:false`), then said "I'm having trouble… right now" and flailed (`drive.download_file` with no id) — while the child was still `running`. Polling is the boss *guessing* via a shared mailbox: `found:false` reads identically whether the child is slow or dead, so it bails. Worse, its narration promised *"I'll notify you as soon as it's ready"* — a promise the system cannot keep (the turn just ends). A real join makes the turn genuinely complete when the child finishes (or fail with the child's actual error). This is the deeper gap flagged in `docs/plans/chat-latency-and-github-tools.md §A`.

**The shape (for the build PR).** Spawn stays cheap (returns `childRunId`); `await_sub_agent` is the explicit, composable join (spawn several, await each / await-all) rather than making spawn block. Child-terminal→parent-signal is added at the executor's terminal-commit site. Termination is now *guaranteed* by ADR-0070's backstop (a wedged child fails terminally within 3 reclaims and fires the signal), so the parent cannot park forever; the wait-ceiling is belt-and-suspenders. This batch ships ADR-0070's backstop + ADR-0072's terminal finalization, which already make the current dead-end **visible and non-infinite**, so shipping the join itself later is safe.

**Alternatives.** (a) **Make `spawn_sub_agent` block until done** — rejected: less composable; can't spawn-then-do-other-work-then-await. (b) **A `get_run_status` tool + smarter polling** — rejected: still polling, still guessing; the signal is event-driven and free given `signalRun`. (c) **Decide chat can't spawn at all** (force-escalate to a brief run) — considered; rejected because the join makes in-chat delegation correct, and delegation is wanted.

**Cross-ref.** Reuses ADR-0034's `wakeCondition`/HIL parking machinery and the sub-agent model (ADR-0016/0026/0035). Depends on ADR-0070 (guaranteed child termination) and composes with ADR-0072 (honest failure surfacing).

**Amendment (2026-06-25, PR #274 review).** The join shipped, and review (Codex + the prior nitpick pass) found the single in-band signal is not enough on its own — `findResumableRunIds` sweeps only `('pending','runnable')`, never `waiting`, so any dropped/never-fired/swallowed signal strands the boss **forever** (lesson `agent-waiting-wake-needs-deadman-timer`). The "wait-ceiling" (#4) was decorative: it only runs *on* a wake, which is exactly what fails. **Built now:** (i) a **dead-man timer** — every `parked` schedules a delayed self-wake job (`sub-agent-join-wake-{queue,worker}.ts`, mirroring the approval-expiry split) at `AWAIT_SUB_AGENT_CEILING_MS`; on fire it re-reads the (terminal-by-then) child and signals the parent, collapsing the lost-wakeup race, the cancelled-child path, worker-crash, and a swallowed signal into one bounded backstop, and making the ceiling load-bearing; (ii) `cancelRunInTx` now wakes a parent joining a cancelled child **in-tx** (prompt, not ≤6-min) — `cancelled` is terminal for the join but the worker only signalled on `completed|failed`; (iii) `await_sub_agent` is hidden from sub-agents (boss-only; the dispatcher rejected it anyway).

**Deferred — finalization invariant (#268, full fix).** The join is still *prompt-driven*: nothing at boss finalization blocks a final answer while spawned children are nonterminal — the exact #268 abandonment shape, now reliable *when the boss remembers to await* but not *guaranteed*. The chosen fix (decided 2026-06-25) is **force-wait**: at finalization with outstanding children, re-route through the await machinery (await each, one more boss turn with their results) rather than mark-incomplete. Deferred to its own PR because forcing it requires synthesizing the await call + its assistant tool-call into the transcript (an orphan tool-result otherwise breaks the next model turn) — real feature work with transcript-protocol implications, not a nitpick fix. Until then the reliability backstops above guarantee the turn cannot hang; the gap is that an un-awaited child's result may simply not be incorporated.
