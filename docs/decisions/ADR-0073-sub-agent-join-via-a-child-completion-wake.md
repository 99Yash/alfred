# ADR-0073 — Sub-agent join via a child-completion wake signal, not scratch-polling (BUILT + reliability backstops PR #274; finalization invariant deferred — see amendment)

**Decision (designed, not yet built).** The boss waits on a spawned sub-agent by **parking on a wake-condition that the child fires when it reaches a terminal state**, replacing the current fire-and-forget + N-times-`read_scratch` + apologize. Reusing the existing `wakeCondition`/`signalRun` machinery (service.ts): **(1)** a new tool `system.await_sub_agent(childRunId)` sets `wakeCondition {kind:'signal', name:'sub_agent_done:<childRunId>'}` and parks the parent step as `waiting`; **(2)** when a child run commits to a terminal status (completed/failed/cancelled), the executor reads `metadata.parentRunId` and calls `signalRun(parent, 'sub_agent_done:<childRunId>')`, flipping it `runnable`; **(3)** `await_sub_agent` returns the child's real outcome — terminal `status` + `output` + `error` from `agent_runs` — so the boss reports the truth instead of inferring from a scratch key; **(4)** a defensive parent wait-ceiling; **(5)** a rubric line: never promise an out-of-turn notification — there is no async notify path, so either complete in-turn or fail honestly now.

**Why.** Dev-proven (#268): the boss spawned a child, polled `shared.pdf_file_id` 4× (`found:false`), then said "I'm having trouble… right now" and flailed (`drive.download_file` with no id) — while the child was still `running`. Polling is the boss _guessing_ via a shared mailbox: `found:false` reads identically whether the child is slow or dead, so it bails. Worse, its narration promised _"I'll notify you as soon as it's ready"_ — a promise the system cannot keep (the turn just ends). A real join makes the turn genuinely complete when the child finishes (or fail with the child's actual error). This is the deeper gap flagged in `docs/plans/chat-latency-and-github-tools.md §A`.

**The shape (for the build PR).** Spawn stays cheap (returns `childRunId`); `await_sub_agent` is the explicit, composable join (spawn several, await each / await-all) rather than making spawn block. Child-terminal→parent-signal is added at the executor's terminal-commit site. Termination is now _guaranteed_ by ADR-0070's backstop (a wedged child fails terminally within 3 reclaims and fires the signal), so the parent cannot park forever; the wait-ceiling is belt-and-suspenders. This batch ships ADR-0070's backstop + ADR-0072's terminal finalization, which already make the current dead-end **visible and non-infinite**, so shipping the join itself later is safe.

**Alternatives.** (a) **Make `spawn_sub_agent` block until done** — rejected: less composable; can't spawn-then-do-other-work-then-await. (b) **A `get_run_status` tool + smarter polling** — rejected: still polling, still guessing; the signal is event-driven and free given `signalRun`. (c) **Decide chat can't spawn at all** (force-escalate to a brief run) — considered; rejected because the join makes in-chat delegation correct, and delegation is wanted.

**Cross-ref.** Reuses ADR-0034's `wakeCondition`/HIL parking machinery and the sub-agent model (ADR-0016/0026/0035). Depends on ADR-0070 (guaranteed child termination) and composes with ADR-0072 (honest failure surfacing).

**Amendment (2026-06-25, PR #274 review).** The join shipped, and review (Codex + the prior nitpick pass) found the single in-band signal is not enough on its own — `findResumableRunIds` sweeps only `('pending','runnable')`, never `waiting`, so any dropped/never-fired/swallowed signal strands the boss **forever** (lesson `agent-waiting-wake-needs-deadman-timer`). The "wait-ceiling" (#4) was decorative: it only runs _on_ a wake, which is exactly what fails. **Built now:** (i) a **dead-man timer** — every `parked` schedules a delayed self-wake job (`sub-agent-join-wake-{queue,worker}.ts`, mirroring the approval-expiry split) at `AWAIT_SUB_AGENT_CEILING_MS`; on fire it re-reads the (terminal-by-then) child and signals the parent, collapsing the lost-wakeup race, the cancelled-child path, worker-crash, and a swallowed signal into one bounded backstop, and making the ceiling load-bearing; (ii) `cancelRunInTx` now wakes a parent joining a cancelled child **in-tx** (prompt, not ≤6-min) — `cancelled` is terminal for the join but the worker only signalled on `completed|failed`; (iii) `await_sub_agent` is hidden from sub-agents (boss-only; the dispatcher rejected it anyway).

**Amendment (2026-07-26) — the child streams its trail into the parent's chat turn.** A `spawn_sub_agent` card said "Delegating a sub-task" and then nothing: the child could burn a dozen tool calls and a minute of wall time invisibly, and the next thing the user saw was the boss answering. The card is now the child's own live activity trail. Two things this pins:

- **A persisted chat origin.** `agent_runs.metadata.subAgent` gains `chat: { threadId, messageId }` (`subAgentChatOriginSchema`), written at spawn when the parent is a chat run. It is optional by construction — a cron brief or any background boss spawns children with no thread, and those simply run without a trail. A _partial_ origin is rejected at parse rather than half-published, because a `threadId` with no `messageId` addresses a turn the client cannot key.
- **A cross-run event-addressing rule.** A child publishes `chat.tool` events into its **parent's** address: every top-level field (`runId`, `threadId`, `messageId`) is the parent's, and the child's own identity rides in `subAgent { parentToolCallId, subId, childRunId }`. The client keys its in-flight turn on `(messageId, runId)`, so a child publishing its own `runId` would read as a brand-new turn and blank the bubble mid-stream. `packages/api/.../workflows/tool-card-events.ts` is the single builder for these payloads so the rule cannot be violated by a hand-written literal, and it clamps the provider-supplied `toolName`/`toolCallId` to the wire caps — an over-long model-invented name must bounce as `unknown_tool` and self-correct (ADR-0070 / #267), not throw inside a commit hook and kill the run.

Two client invariants follow from the child outliving its parent turn (a spawn need never be awaited, and a cancel reaches a child only cooperatively — see the 2026-08-16 amendment): a sub-agent event may **address** an in-flight turn but never **create** one (`subAgentEventAddressesStream`), and a terminal tool card is **absorbing** — the resume/reclaim path re-dispatches a whole batch and republishes its `started`, which must not un-finish a landed step.

**Amendment (2026-08-16, #559b) — a cancel now cascades to the children.** The original text said a cancel does not reach a child. That was not a decision; it was the absence of one, and #559b made it a correctness hole. The cancellation fence lives on one `agent_runs` row: a child holds its own fence at generation 0, so a boss that dispatches an effect after its cancel is refused while the child it delegated to keeps writing. **Built:** (i) `cancelRunInTx` cancels every non-terminal sub-agent child on the parent's transaction, bumping each child's own fence and publishing its `agent.run` frame; a child's only post-commit obligation is its staging sweep (rejecting the approvals it still held open), which rides back in the parent's `afterCommit` closure — a sub-agent owes no client closure and no scratch snapshot; the recursion terminates on the status guard (a run this transaction already cancelled reads `already_terminal`), so a metadata cycle cannot loop; (ii) `spawnSubAgent` reads the parent row `FOR UPDATE` and inserts the child on the same transaction, refusing a terminal parent — a spawn racing the cascade now either lands before it and is cancelled with it, or blocks and is refused, instead of being born orphaned one moment after the cascade listed the children. **Still cooperative, not retroactive** (workflows-v1 § "Cancellation and pause semantics"): the cancelled child keeps running its current step body until its own dispatch gate re-reads its (now bumped) fence, so its in-flight tool cards can still land in the parent's turn. Both client invariants above therefore stand unchanged — they were only ever load-bearing because a child event can arrive late, which a cooperative cancel preserves. **Residue:** the cascade attaches to the `cancel` transition, not to the terminal transition — `markRunFailed` writes `failed` without cascading or bumping the fence, so a boss that dies on a turn limit or a tool error still leaves its children running at generation 0.

**Declined — moving the child's lifecycle onto the same channel.** Review proposed carrying the child's phase on the addressed event (`subAgent.phase`, or a `chat.sub_agent` kind) so one publisher owns both the steps and the trail's terminal state, instead of the client joining `chat.tool` to `agent.run` through a `childRunId → parentToolCallId` map it builds itself. Rejected: `agent.run` is published by the **executor** on every terminal path — including a hard crash, a stale-lease death, and an external cancel — none of which a workflow-level publish inside the brief can reach. The concrete hole in the join (a child with zero tool calls never registers a mapping, so its lifecycle frame is dropped) is harmless, because with no tool call there is no trail to close either. Coverage beats addressing cleanliness here.

**Deferred — finalization invariant (#268, full fix).** The join is still _prompt-driven_: nothing at boss finalization blocks a final answer while spawned children are nonterminal — the exact #268 abandonment shape, now reliable _when the boss remembers to await_ but not _guaranteed_. The chosen fix (decided 2026-06-25) is **force-wait**: at finalization with outstanding children, re-route through the await machinery (await each, one more boss turn with their results) rather than mark-incomplete. Deferred to its own PR because forcing it requires synthesizing the await call + its assistant tool-call into the transcript (an orphan tool-result otherwise breaks the next model turn) — real feature work with transcript-protocol implications, not a nitpick fix. Until then the reliability backstops above guarantee the turn cannot hang; the gap is that an un-awaited child's result may simply not be incorporated.
