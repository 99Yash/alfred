# ADR-0083 — Briefing context signals are a typed middle layer between source evidence and prose, and briefing prose never writes durable facts (BUILT: contract + policy — #415; consumers deferred, under #218)

**Decision.** Everything a briefing writer says about the user's situation flows through **three layers**: **(1) source evidence** — provenance-bearing gather items, each addressable by a validated `BriefingReference`; **(2) typed context signals** — a small, generic vocabulary describing how evidence matters (`development`, `open_loop`, `pattern`, `constraint`), with a required bounded `summary` and non-empty evidence; **(3) generated prose** — the warm paragraph the writer emits, deliberately ephemeral. Domain scenarios do not become enum members: a moved interview and a merged PR are both developments; shipping activity and recurring notification noise are patterns. This keeps the contract about **knowing what is happening around the user**, not predicting which situations Alfred will encounter.

All briefing context signals are **query-time views**, never durable memory. A signal kind does not decide whether truth may be persisted; durable state belongs upstream in its owning domain or ADR-0067 projection and can be cited as evidence. The contract bounds `summary` and evidence fan-out, rejects unknown fields, and requires positive grounding. Its namespace is disjoint from the complete `user_facts.key` gate. Briefing work must not promote document metadata, third-party attributes, or contextual interpretations into identity/org facts; those writes remain governed by ADR-0079/0080.

**Why.** The original first pass mixed four different abstraction levels: workflow state (`open_work_loop`), domain events (`job_search_event`), infrastructure failures (`integration_access_gap`), and interpretations (`shipping_momentum`). It was specific without being complete, so each new user situation would pressure the enum to grow into a catalogue of product guesses. The generic vocabulary is stable across email, calendar, GitHub, health, travel, relationships, and sources not yet connected, while the required summary preserves the actual meaning. Making every signal query-time-only also removes the false implication that durability can be inferred from a presentation category.

**Alternatives.** (a) **Let the composer read gather directly** — rejected: there would be no typed seam for evidence and bounds. (b) **Keep adding scenario-specific kinds** — rejected: it couples a generic context layer to today's integrations and examples. (c) **Make signals durable observations** — rejected: durable truth already has owning domain models and projection policy; persisting a briefing interpretation recreates the memory leak this ADR prevents.
