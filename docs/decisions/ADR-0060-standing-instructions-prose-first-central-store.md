# ADR-0060 — Standing instructions: prose-first central store + a deterministic enforcement carve-out

**Decision.** Generalize standing instructions from the shipped suppress-sender slice (ADR-0058) into a single, future-proof architecture: **one central store, one retriever, prose-first application, with a thin deterministic-enforcement carve-out only where a hard guarantee and cost-sensitivity coincide.** A standing instruction is a durable, user-stated **bias on an existing pipeline** (triage / briefing / meeting-prep) — _not_ a request to author new scheduled behavior (that stays ADR-0017 workflows + ADR-0027 triggers). The store is `user_facts`, `key="standing_instruction"`, **`schemaVersion:2`**: `directive` (resolved prose, always present — the universal carrier), `target?` (matchable descriptor), `enforcement?` (typed+parameterized actions); `action`/`surface` are dropped. A single `getRelevantInstructions(context)` retriever (inject-all-active behind a context-aware interface) feeds every consumer. Agent-driven consumers (chat, briefing **compose**, meeting-prep, **every future feature**) apply the prose by judgment; the deterministic `enforcement` layer is consumed only by triage **classify** and briefing **gather**. Build detail in [docs/plans/long-term-memory-v1.md](../plans/long-term-memory-v1.md); glossary under _Long-term memory_ (CONTEXT.md).

**ADR-0067 amendment (2026-06-23).** `user_facts` remains the standing-instruction **read projection**, not the authoritative write source. Chat/user corrections now enter the append-only observation log as `source='user'|'alfred_chat'` observations; the projection emits the ADR-0060 `user_facts` shape for existing retrievers. This prevents two systems of record for the same intent.

**Why this is its own ADR.** Surfaced 2026-06-17. It is architectural and hard-to-reverse (a stored wire format + an application model a dozen call sites depend on), it **reverses a framing locked six questions earlier in the same session** (an enumerated per-consumer `effects` contract → prose-first), it **refines a repeatedly-enshrined principle** ("category stays honest, never bend it"), and it **amends ADR-0051** by feeding the deliberately context-free cheap classifier a new deterministic signal. Each is hard-to-reverse or surprising-without-context.

**Micro-decisions.**

1. **Prose-first, not an effects enum (the redirect).** The first cut enumerated a symmetric per-consumer `effects` table; the user rejected it as forcing us to "keep up" per feature/integration. The spine flips: the resolved **`directive` prose is the universal carrier**, and the default application is _the consumer's own model reading the directive and applying it by judgment_ — including flagging conflicts / counterproductive effects. A new agent-driven feature gets instruction-awareness for free by calling the retriever; it never extends a contract. Typed effects survive only as the carve-out below.

2. **Deterministic enforcement is a carve-out keyed on "needs a guarantee," not on feature count.** "Stop nagging me" injected as a prompt line is a suggestion the model can ignore — the original Ben-Book bug _was_ a prose-fails-silently bug, and the cheap, high-volume triage classifier (ADR-0051 keeps it context-free) cannot afford per-email judgment. So a thin typed `enforcement` projection (`block/force_todo_suggestion`, `force_category{category}`, `exclude/include_briefing_priority`) is applied deterministically by **triage classify + briefing gather**. It is a **registry**: a _future_ consumer that needs a hard guarantee registers its own enforcement, but ordinary new features use prose-pull. The shipped slice's `effects` enum _is_ this layer, scoped down.

3. **No-double-application.** An instruction with an `enforcement` is applied by the deterministic consumer that owns that effect; a consumer falls back to the prose `directive` only for instructions it has not already enforced. ("Suppress Ben" is dropped by `gather` and never reaches `compose`.) Prevents an instruction firing twice with divergent results.

4. **Category override allowed — but the model never bends it.** Refines the "category stays honest" rule (ADR-0058 slice / ADR-0059). The _classifier_ still never invents significance; an **explicit user instruction** may re-stamp the category, via the deterministic override layer (`force_category`), _after_ honest classification — exactly like the existing security override-floor. The distinction is authority (the user) vs hallucination (the model). **Every override logs an audit breadcrumb** (`overriddenByInstruction:{factId,from,to}`) — a force-stamped category must never be traceless.

5. **Schema v2: `directive` + `target?` + `enforcement?`; drop `action`/`surface`.** `directive` carries display intent, `enforcement` carries the operational contract, so the two human labels were redundant. `target` is optional (a pure free-text rule has none) and serves both deterministic exact-match and prose relevance-filtering. The reader handles v1 rows; prod has a handful, so migration is near-free.

6. **Conflict is gated at capture, two mechanisms.** **Structural** conflict (overlapping `target` + opposing `enforcement`, or target subset/superset) is detected **in the `system.remember` tool** — `status:"conflict"` + the conflicting fact(s) (mirrors `resolve_todo`'s `ambiguous`, extends `already_exists`); the tool **never silently overwrites a contradiction** (relying on the model to notice is the prose fragility again). **Semantic/counterproductive** conflict ("mute all of @oliv.ai" hides the manager) is the **boss's** job, reasoned from existing instructions + `read_user_context`. In both, the boss **poses a counter-question / offers options** instead of writing through; a confirmed reversal supersedes via `supersedes_id`. An **offline/passive** capture that hits a conflict **holds the write as `proposed`** — never silent overwrite.

7. **Resolve-at-write hardened for multi-candidate disambiguation.** When the user's words match more than one known entity ("Ben" → two people), canonical resolution remains a write precondition: >1 candidate → the boss surfaces them and **asks which**; 0 confident → a one-line clarifying question; exactly 1 → proceed. Person/sender targets resolve via the team graph (`upsertPersonByAlias`/`entities`).

8. **Precedence at apply-time: specificity-then-recency, with a safety carve-out.** Multiple matching instructions → most-specific `target` wins (`sender_email`/`person` > `sender_domain` > `category` > `topic`), newest breaks ties. `enforcement` is authoritative over the model's intrinsic judgment for the dimension it touches. **The protective override-floor in `classify.ts` (force-`urgent` on exposed-secret / account-compromise) outranks a user _down-rank_ but never a user _up-rank_** — a mute can't bury an irreversible-harm alert; an elevate stacks. Named, floor-only, logged.

9. **A minimal review surface is in scope (not deferred).** A `/settings` "Standing instructions" panel — each active rule's plain-English `directive` + undo/reject + edit, over the already-synced facts (`row_version`) and the existing reject/edit mutations. Required because positive instructions **actively mislabel** mail; audit cannot be logs-only. **Notification unchanged** (ADR-0056 + slice): a chat-stated instruction sends no email; only passive/background-captured instructions notify.

**What this amends / builds on.**

- **ADR-0058** — generalizes the suppression slice; the suppression row becomes the `enforcement`-bearing special case of schema v2. The slice's "polished changelog deferred" is superseded by micro-decision 9.
- **ADR-0051** — adds a deterministic standing-instruction signal (the `enforcement` layer) to the context-free cheap classifier; consistent with its deterministic-context posture (no per-email LLM judgment added).
- **ADR-0056** — governance/notify/reversibility carry over unchanged; capture is the chat→memory write path (ADR-0057), now with structural-conflict gating.
- **ADR-0059** — refines the shared "category stays honest" principle: the model still never bends; an explicit user instruction may, logged.
- **ADR-0017 / ADR-0027** — the scope boundary routes "author new scheduled behavior" to workflows/triggers, not standing instructions.

**Alternatives.**

- (a) **Enumerated per-consumer `effects` contract (the first cut).** Rejected: couples every feature/integration to a shared enum we must keep in sync; a new feature should get instruction-awareness for free.
- (b) **Prose-everywhere, including triage.** Rejected: "stop nagging me" becomes a suggestion the cheap classifier can ignore (the Ben-Book failure) and would amend ADR-0051 to feed the hot path per-email judgment.
- (c) **Keep the category sacrosanct; route positive intent to surfacing-only effects.** Rejected: "tag it urgent" then never labels it urgent — fails the literal user intent.
- (d) **Detect structural conflict in the prompt only.** Rejected: same fragility as prose-only suppression; structural contradictions must be caught deterministically.
- (e) **Semantic relevance-filtering in the retriever from day one.** Deferred: the instruction set is bounded; inject-all-active behind the context interface is enough, and filtering is a swap behind the same signature.
- (f) **Raw reject-mutation only, no review panel.** Rejected: positive overrides silently distort triage; the user needs one place to see and undo them.
