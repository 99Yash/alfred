# ADR-0101 — Context Search is a read-boundary module: registered source adapters, one bounded envelope, no source names in consumers

**Decision.** Cross-integration retrieval gets a new `@alfred/assistant` module, `context-search`, with ONE read-only verb. `searchContext` takes a bounded query/task envelope (`ContextSearchRequest`) and returns a bounded, source-attributed result (`ContextSearchResult`). Sources are `ContextSource` adapters registered by stable id with `registerContextSource`, each carrying a required capability manifest (#466); the boundary enumerates them internally, selects them by what they declare, and never branches on a source name. Slice 1 wired no model-facing tool to it; #426 later added the `system.search_context` tool over the `SystemToolContextSearchAdapter` boot seam.

**Naming.** Epic #422 calls the concept the "Context Fabric". This module is `context-search`, because `context` alone is overloaded across this tree and the boundary's one verb is `searchContext`. The epic keeps its own name; the code stays literal.

Sub-decisions:

1. **A new module, not a fold into an existing one.** The boundary aggregates `@alfred/corpus search`, knowledge `recallMemory` / `readUserContext`, the ADR-0067 `userModelReader`, the object-state store, and later live read-only tools. Each of those subtrees must be able to feed the boundary without importing it, so it cannot live inside any one of them without a cycle.
2. **The source set is data.** `registerContextSource(source)` keys on `source.id`, so adding a native integration or an MCP-backed source is one registration and no chat, briefing, todos, or meeting-prep caller changes. Re-installing the same instance is a no-op; a different instance under a live id throws.
3. **The envelope is validated at the boundary, and owned in contracts.** `contextSearchRequestSchema` bounds `userId`, `query`, `task`, and `limit` before any source runs, and it lives in `@alfred/contracts` with its `CONTEXT_SEARCH_DEFAULT_LIMIT` / `CONTEXT_SEARCH_MAX_LIMIT` caps. The model-facing `system.search_context` tool (#426) derives its bounded input from the same shape and cap rather than inventing a second one.
4. **The result is source-attributed and honest.** Every consulted source gets a report: `ok`, `empty`, or `error`. `empty` and `error` are distinct facts; a throwing source becomes one `error` report carrying `toMessage(error)` and never fails the whole read. Absence is reported, never inferred as a closed loop.
5. **No adapter returns raw bytes or full bodies.** A card carries only a bounded snippet (or an honest note when there is no text). #423 defined the card's `citations` and opaque `expansion` handle; #424 added `score`, and the first adapters fill all three. Provider-specific action tools are never invoked by the boundary.
6. **The evidence card is the canonical shared contract (#423 superseded the provisional one).** Slice 1's module-internal `ContextEvidence` was provisional; #423 replaced it with `EvidenceCard` / `evidenceCardSchema` in `@alfred/contracts` and the `packEvidenceCards` renderer in `context-search/pack.ts`. Source adapters, the packer, the source capability manifest (#466), and the later `system.search_context` tool (#426) build on the card; #429 extends media kinds. The packer takes a read result (cards plus per-source reports), not a bare card list, so honest missing/failed notes are structural rather than optional.
7. **Ranking is deterministic, and it runs before the truncation (#427).** Slice 1 deferred ranking: cards came back in source-registration order and the combined list was truncated to `limit`, so an early source could fill the budget and a strong card from a later source was dropped before anything compared them. `rankEvidenceCards` replaces that order, and `searchContext` ranks first and truncates second. See sub-decision 12 for the ranker itself.
8. **Discovery is the manifest's job (#466 landed it; see sub-decisions 14-16).** Registration carries the declaration, so registration is still the only contract a source signs. An unknown or minimally described MCP source stays a callable tool and is not a trusted retrieval source until its manifest declares read semantics and authority.
9. **Degradation is the default.** With no adapter registered the boundary returns an empty typed result rather than throwing, so a caller can be written before any adapter exists.
10. **The module boundary is the public surface.** `context-search` exposes one verb (`searchContext`), its result shape, the registration function, and the manifest reader through its `index.ts`; the source registry enumeration stays internal so a future caller cannot bypass selection. `check:architecture` covers package and module edges, not the per-symbol surface — keeping a second door closed is this index's job, by not exporting it.
11. **The first adapters are installed at the composition root (#424).** `documents` wraps `@alfred/corpus search` over `chunks ⨝ documents`, and `memory` wraps `recallMemory` over `memory_chunks`. Both live privately inside the module and are installed together by the exported `registerDefaultContextSources`, which `apps/server` calls during boot. One adapter covers every ingested provider, because the corpus is already source-tagged and the search is source-agnostic; the per-record provider rides the citation, not a per-provider clone of the adapter. A card's `score` is source-native (cosine similarity) and comparable only within a source; the packer never renders it, and #427 normalizes across sources. Installing the defaults is memoized so a repeat boot call re-registers the same instances rather than throwing on the duplicate-id guard.
12. **The ranker is a pure function over declared card fields, and an absent signal drops its feature (#427).** `rankEvidenceCards(cards, context)` scores each card as a weighted AVERAGE over the features it can supply — `semantic`, `exactMatch`, `recency`, `freshness`, `authority`, `sourcePriority`, `objectState`, `focus`, `userModel` — and ties break on `EvidenceCard.id`. Four properties make it the ranker this boundary can keep:
    - **No LLM reranker, and no clock of its own.** Every feature is arithmetic over a field the card already declares, and `now` is an input. The same cards and the same context produce the same order on every call, so a ranking change is a code change rather than provider weather. A model-based reranker stays a separate, later decision.
    - **A feature a card cannot supply is DROPPED from its average, never defaulted to zero.** A card with no timestamp is not ranked as infinitely old, a card with no `score` is not ranked as scoring zero, a card with no `object` carries no `exactMatch` or `focus` feature, and an undeclared `authority` is never promoted toward `high` nor pushed below a source that honestly declared itself `low`. The two deliberate exceptions are `freshness` and `authority`, which read silence as `unknown` (a conservative default, not a zero). This is the card contract's own honesty rule applied to ranking: absence is reported, never inferred.
    - **`score` is normalized WITHIN its source, because the contract says it is comparable only there.** A source whose scores all fall in `[0, 1]` is left alone — that is already the shared convention, and min-max would rescale a source's three worthless hits into a perfect 1. Any other scale is min-max normalized inside the source, where only the ORDER is trustworthy.
    - **Ranking metadata is a sibling of the evidence, not a field on a card.** `ContextSearchResult.ranking` is parallel to `evidence`, carries each card's combined score and its present features, and is never handed to `packEvidenceCards`. The `system.search_context` runtime adapter emits it as a debug log per read, so a production trace carries the winning order without the model seeing it; a test or a retrieval eval (#430) reads it here.

    The one signal not derivable from a card is the ADR-0067 user-model weight. No
    builder lives in this slice: `EvidenceRankContext.entitySignificance` is a
    seam #431 fills (it also populates `EvidenceCard.entities`), and until then
    `searchContext` passes no map, so the `userModel` feature is absent from
    every card. A ranking input may never fail a search.

13. **Manifest-driven source priority is a seam, not a switch (#466).** `EvidenceRankContext.sourcePriority` is a `Map` from `ContextSource.id` to a priority in `[0, 1]`. The manifest folds a source's declared authority, freshness, and cost into that one number; sub-decision 16 is the fold. Every registered source folds to a number — an undeclared axis scores its `unknown` row and the divisor is the fixed total weight — so the ranker always carries the feature and silence agrees with declared `unknown`.

14. **A source declares itself at registration, and the declaration is REQUIRED (#466).** `ContextSource.manifest` is a required `RetrievalSourceManifest` (`@alfred/contracts/source-manifest.ts`): at least one read capability and an authority above `unknown`. `registerContextSource` parses it with `retrievalSourceManifestSchema` — which strips unknown keys — stores the parsed, frozen value beside the original instance, and rejects a manifest whose `id` differs from the source's id, so "registered but undescribed" cannot exist and a malformed or half-described manifest stops a boot rather than a read. `manifest.read` must equal the keys of `ContextSource.reads` in both directions (adapters build both through `defineContextSource`, so the declaration derives from the readers that exist), so a declared capability with no reader and a reader with no declaration both fail at boot. `SourceManifest` stays loose for the catalog case: a source that knows nothing about itself still writes `{ id, kind: "mcp" }`, and a catalog reader treats that silence conservatively instead of inventing a value for it. An OPTIONAL manifest was rejected — it would create a second, quieter degradation path beside the one this contract exists to define, and the two would drift.

    The manifest does not restate ADR-0093, because non-duplication here is a JOIN and not a copy. A native source names its `integration` slug, and `sourceManifestDisplayName` / `sourceManifestDomains` read the display name and the host back out of `INTEGRATIONS`; the join is implemented and covered from a fixture, but no built-in source names a slug today: renaming an integration still renames its source without a second spelling to go stale, while Alfred's own stores (`documents`, `memory`, `object-state`) each span every ingested provider at once, so they declare their own display name and no slug and leave the catalog-reserved declarations (`objectKinds`, `mediaKinds`, `identityKeys`, `indexability`, `discovery`) unset. The boundary branches only on `read`, `availability`, `authority`, `freshness.typical`, and `cost.class`.

15. **Sources are SELECTED before they are read, and every exclusion is reported (#466).** `searchContext` calls `selectContextSources` first. Two declarations exclude a source: its boot-time manifest says `availability: "unavailable"` (a static, registration-time admission, not a live health reading — a source that fails mid-process reports `error`); or none of its declared read capabilities answers this request (an `exact_lookup`-only source is not asked a free-text question that carries no `objects`; `enumerate` / `expand` are declared vocabulary for #428 and do not qualify here). Silence is never read as unavailable — an undeclared `availability` is still consulted, because a missing statement is not a confession.

    `retrievalSourceManifestSchema` requires the other two declarations at registration, and neither is inferred: some read capability, and an `authority.level` above `unknown`. The authority half is not tidiness. `semantic` is the ranker's heaviest feature and `normalizeSemanticScores` leaves a source alone whose scores already sit in `[0, 1]`, so an undescribed source that returns `score: 1` on every card would otherwise rank itself first. Requiring a declared provenance closes that structurally, at registration, rather than by a ranking penalty that a confident enough `score` can outweigh. `isTrustedRetrievalSource` in `context-search/manifest.ts` remains the boundary-side predicate for that same rule until a web catalog must agree on it.

    **The trust rule is uniform across `kind`.** A first-party source that describes itself as little as a stranger is trusted as little. Trust follows the declaration, never the author — a rule that exempted `internal` would make the manifest advisory for exactly the sources most likely to be read.

    `ContextSourceStatus` gains a fourth member, `skipped`, carrying the closed `SourceExclusionReason` enum (`unavailable` / `no-answering-read`), and `packEvidenceCards` renders it as `<id>: not consulted (<plain words>)` with `error` notes first so a routine skip never hides a failure. "Never asked" and "asked and found nothing" are different facts, and sub-decision 4's honesty rule applies to the sources as much as to the evidence. Reports stay in REGISTRATION order, so a reader comparing two traces never sees the source list reshuffle because one manifest started excluding a source. Selection is not a router: it reads declared capability only, never `discovery.topics` and never the query text. Choosing sources by guessing at intent is the hard-coded switch this boundary exists to remove.

16. **The manifest fold is the ranker's, and the numbers live with the ranker (#466).** `sourcePriorityFromManifest` in `rank.ts` folds one manifest into the single `[0, 1]` priority sub-decision 13 reserved, as a weighted combination over authority `0.6`, freshness `0.25`, and cost `0.15`, divided by the fixed total weight. Authority leads because it is the only one of the three that says anything about whether the source's evidence is RIGHT; cost has no bearing on truth at all and only ever breaks a tie. An undeclared axis scores its `unknown` row, so silence and a declared `unknown` agree and omission buys nothing — dividing by the present weight instead would reward it, because an omitted axis would then read as a declared maximum. The weights sit in `rank.ts` and not in the contract because they are ranking judgements, not facts about a source: `@alfred/contracts` states what a manifest MEANS, the ranker decides what to do about it, and a reweighting is then one file's change. A card's own `authority` feature reads the same declaration: adapters stamp it from the manifest via `sourceAuthorityFromManifest`, so the trust fact reaches the ranker's larger feature as well as the smaller `sourcePriority` one.

17. **A source declares WHAT it expands, and the phase routes by that declaration alone (#1077).** `SourceManifest.expansionKinds` names the `EvidenceCard.expansion` handle kinds a source dereferences, and `registerContextSource` binds it to the `expand` read capability in both directions: a source that claims `expand` and names no kind fails at boot, and a source that names kinds without the capability fails at boot. Neither half can be inferred from the other, and each half alone is a source that registers and then routes nothing — the silent dead declaration the manifest contract exists to stop. `expansionRoutes` folds the declarations into one kind-to-source table, and the expansion phase reads that table and NEVER the `sourceId` the handle itself carries. A card that picked its own reader would be the per-integration name switch this boundary exists to remove; the handle's `sourceId` stays a debugging fact. Two sources that declare one kind is a composition-root ambiguity rather than a read failure, so the first REGISTERED source wins and the route stays stable across reads. A source whose manifest declares `availability: "unavailable"` routes nothing, because a boot-time admission applies to both phases.

    **A source that only expands gets its own skip reason.** `SOURCE_EXCLUSION_REASONS` gains `expansion-only`, and `packEvidenceCards` renders it as `only re-reads records other sources found`. It is not a weaker `no-answering-read`: a source that cannot answer this question will not be asked at all, while a source that only expands answers a DIFFERENT question and the read may still reach it in the second phase. Sub-decision 4's honesty rule says the two facts must not collapse into one word the model reads as "this source had nothing on the topic". `expand` therefore leaves the catalog-reserved set of sub-decision 14; `enumerate` stays reserved, because listing recent records still ignores the question.

18. **The phase runs AFTER the rank and the truncation, and it replaces a card rather than appending one (#1077).** `searchContext` collects, ranks, truncates, and then expands. Running the phase earlier would pay a provider round trip for cards the `limit` was about to drop, and a live refresh would change the very scores that decide the order. Five rules make the phase safe to keep on by default:

    - **Only a surviving, non-live card with a routable handle is a candidate**, and the walk is best-first, so `CONTEXT_SEARCH_MAX_LIVE_EXPANSIONS` (five, far below `CONTEXT_SEARCH_MAX_LIMIT`) always spends its budget on the strongest evidence. Two cards that share one `(kind, ref)` cost ONE call, and only the better-ranked position is replaced — replacing both would put one card id in the evidence twice.
    - **The expanders run in parallel under a phase deadline**, because the phase is the read's only network cost and calling N providers in series would make the read's latency the sum of theirs. Each attempt swallows its own failure, so one broken provider cannot reject the batch — and the deadline (`CONTEXT_SEARCH_EXPANSION_TIMEOUT_MS`) is what stops one HUNG provider from delaying it: every expander receives the phase's abort signal, and the phase stops waiting at the deadline. The count cap bounds how many round trips the read pays for; only the deadline bounds how long it waits.
    - **A refreshed card must declare `time.freshness: "live"` itself.** The boundary validates it exactly like a collected card, additionally requires the `source.id` join key and that live declaration, and REJECTS a refresh that omits it rather than stamping it. Alfred inferring freshness is the one thing the card contract forbids.
    - **A failure is local.** A throwing expander, a contract violation, a missing live declaration, and a timed-out expansion all leave the original card in place. An expansion-only source reports `error` against itself; a source that already answered the query keeps its status and only its count moves, because the expansion answered a different question. An expander consulted but returning nothing leaves the `expansion-only` skip standing, never `empty` — it was never asked the query. An expansion that could not run never costs the read the local evidence it already had.
    - **The caller owns the budget, not the model.** `contextSearchRequestSchema` carries `expand`, defaulting to on, and a caller that cannot pay a provider round trip sends `false` to skip every expander at once. `searchContextInput` (#426) OMITS the field alongside `userId`: whether a read may pay for live round trips is a latency and money decision the server makes, not a knob the model can price, and the omission also saves schema bytes on a kernel tool.

    **The reports stay one per registered source, in registration order.** An `expansion-only` skip the phase consulted reports its real outcome in its registration position — `ok` with the refreshed cards, `error` on failure, and the skip itself when it returned nothing; a first-phase `error` still stands, because the source did fail to answer the query. `evidenceCount` TRANSFERS from the origin source to the expander when a refresh lands: a refreshed card is contributed by the live source and no longer by the source it replaced, and without the transfer both would claim one card and the packer would report a refreshed card as an item it had dropped. An answered STATUS never degrades — a source that answered still reports `ok` even when every card it contributed was refreshed away, and an expansion failure never rewrites it to `error`. The one mirror: an `empty` source whose refresh landed becomes `ok`, because it now has a card in the pack. `ContextSearchResult.ranking` is NOT rewritten: the phase does not re-rank, so a refreshed position's row still names the card the refresh replaced, which is what makes the refresh visible in a trace.

    No provider adapter lands with this decision. A test expander proves the whole path; #428 registers the first real one.

## Why a boundary instead of per-integration activity tools

The alternative is a curated `<integration>.recent_activity` tool per provider and a consumer that calls several of them and merges by hand. That answers a one-source question and never the cross-source one: the consumer owns the merge, so every new source edits chat, briefing, todos, and meeting prep. It also pushes source identity — which provider, which freshness, which authority — into prose the model has to reason about. The boundary makes the merge and the source attribution one deterministic surface, and makes the source set data.

This is the same split ADR-0071/0074 already draw for tools: a curated per-integration read stays a curated tool, and the moment a question spans integrations it belongs here.

## Alternatives

- **(a) Fold into `knowledge`.** Rejected. `knowledge` feeds the boundary (recall, user context, the projection), so the boundary importing `knowledge` while `knowledge` imports the boundary closes a cycle `check:architecture` refuses. The boundary also reads `corpus` and `connections`, which `knowledge` does not own.
- **(b) One `<integration>.recent_activity` tool per provider.** Rejected. The merge moves into every consumer and each new source edits all of them.
- **(c) Return raw `SearchHit`s.** Rejected. They are unbounded, source-typed, and can carry a full provider body; the boundary exists to return bounded, source-attributed cards.
- **(d) Build the ranker and manifest first.** Rejected for this slice. Adapters need a boundary shape to target; the shape is the prerequisite, not the ranker.
- **(e) Give the boundary drill-down and action powers.** Rejected. The boundary is read-only by construction; provider-specific actions stay separate tools, and live expansion (#428) is bounded read-only.
- **(f) Rank with an LLM reranker (#427).** Rejected as the default. A reranker adds a model call and a per-call cost to every cross-source read, and it makes the order unreproducible — the same corpus can come back in a different sequence, which a retrieval eval (#430) cannot regress against and a trace cannot explain. The deterministic features answer the ties this boundary actually has. A reranker can be added later ON TOP of a stable order; it cannot be removed from underneath one.
- **(g) Normalize `score` globally across sources (#427).** Rejected. The card contract states that `score` is comparable only within one source. A global min-max lets one source's scale decide every other source's place: three cosine hits at `0.11`, `0.10`, `0.09` would have their best rescaled to a perfect `1` and outrank a genuinely strong `0.9`.
- **(h) Put the ranking score on `EvidenceCard` (#427).** Rejected. The card is what `packEvidenceCards` renders for the model, so a score on the card is one forgotten line away from being prompt text — and a number the model can see is a number the model can argue with. The parallel `ContextSearchResult.ranking` array cannot leak, because the packer is never given it.
- **(i) Route an expansion by the `sourceId` the handle already carries (#1077).** Rejected. The handle is minted by the card, so routing on it lets a source name its own reader, and a consumer reading a trace would then have to know which provider hides behind which id — the source-name coupling the whole boundary exists to remove. Routing by declared `kind` means a provider gains a live reader by registering one manifest, and the `sourceId` stays a debugging fact.
- **(j) Expand before the rank, or expand every card (#1077).** Rejected. Expanding before the rank pays a provider round trip for cards the `limit` is about to drop, and a live refresh then changes the very `freshness` and `recency` scores that decide the order, so the rank would grade evidence it had itself altered. Expanding every card turns a fifty-card read into fifty provider calls. The phase runs on the truncated list and caps at `CONTEXT_SEARCH_MAX_LIVE_EXPANSIONS`.
- **(k) Let the model set `expand` per call (#1077).** Rejected. The flag is a latency and money budget, and the model cannot price a provider round trip it does not pay for. `searchContextInput` omits it beside `userId`, so the server's default applies to every model-issued read and the kernel tool spends no schema bytes on the choice.

## Residual risk

- **The card surface may still churn.** `EvidenceCard` is canonical and shared, but it is young: `EvidenceCard` grew from a provisional module-internal element, and #425/#429 will extend object-state and media fields additively.
- **The source-set promise now has one real caller.** Three adapters are registered at boot (#424, #425), and `system.search_context` (#426) reads the boundary through the `SystemToolContextSearchAdapter` seam, so "a new source needs no consumer edit" is exercised by a real tool. It is still one consumer, not several: the promise is proven for chat, not yet for briefing, todos, or meeting prep.
- **The ranker's weights are a judgement, not a measurement.** The feature set and the order of the weights are argued from the card contract, and the tests pin the ORDER each weight is supposed to produce rather than any score. Nothing yet measures whether that order retrieves better evidence; the retrieval eval over expected evidence ids (#430) is what would.
- **Per-source HEALTH is still not a ranking signal.** #466 met the first of #427's three open criteria: manifest-declared authority, freshness, and cost now exist and the fold reaches the ranker. Health remains unmet, and the manifest does not supply it — `availability` is a source's own STATIC declaration, not a live reading. `ContextSourceReport.status` cannot serve either, because a source that reports `error` returned no card for the ranker to place, and `connections/event-source-health.ts` keys on EVENT sources rather than the internal store ids (`documents`, `memory`, `object-state`) the cards carry. A durable per-source health reading needs its own slice. "Thread continuity" is not met: no card carries a thread and the envelope carries no conversation id, so there is no thread reading at all. The `focus` feature reads the caller's declared exact `objects` instead — a narrower honest signal, distinct from `exactMatch` (which reads the card: any resolved object scores 1 — while `focus` reads the request: only a declared object scores 1). A thread-scoped entity set lands with #431.
- **Dropping a feature rewards silence over an honest bad reading.** A dropped feature leaves the card's average, so the card scores the mean of its remaining features. A card that honestly declares a 200-day-old instant therefore ranks BELOW an otherwise identical card that declares no instant at all. The decision stands — imputing a zero would punish silence, which is the failure the card contract exists to prevent — but the cost is real and it is the reverse of the intuitive reading. Imputing the corpus median per feature is the alternative, and it needs the retrieval eval (#430) to choose between them rather than an argument.
- **A self-reported `score` is the strongest feature — closed at registration by #466.** `semantic` carries the largest weight, and `normalizeSemanticScores` leaves a source alone whose scores already sit in `[0, 1]`, so an undescribed source returning `score: 1` on every card would take `semantic = 1` and its `unknown` authority (weight `0.1`) could not offset it. Registration closes this structurally rather than by a ranking penalty: a source with no declared authority cannot register, so it produces no card whose `score` the ranker could read. The residue is narrower and it is a real one — a source that declares a HIGH authority it does not deserve is trusted at face value. The manifest is a source's own statement, and nothing audits it.
- **A first-party adapter that forgets to declare authority fails at boot.** Sub-decision 15's uniform trust rule is deliberate, and registration enforces it: an adapter shipped with no `read` or with no authority above `unknown` throws from `registerContextSource` — a compile error for a literal, a parse throw otherwise — instead of going dark behind a `skipped` line. The old silent-dark failure (a passing `pnpm check`, an accepted manifest, a boundary answering normally with one `not consulted` line as the only evidence) is what the strict `RetrievalSourceManifest` subtype removes.

- **The user-model signal is a seam, not a read on the search path.** No builder
  lives in this slice: the per-entity weight formula (`base(components) *
recency(asOf)`, ADR-0067 D6) is owned by the user-model substrate, and
  rebuilding any version of it in the ranker would put a second, drifting copy
  next to the projection. #431 builds the signal and populates
  `EvidenceCard.entities`; until then the `userModel` feature is absent from
  every card at zero search-path cost.
- **A dropped object-state miss card is less visible than a dropped hit.** A card that resolved no object ranks near the bottom by design, so a tight `limit` now drops the honest "this key resolved nothing" card before it drops a resolved one. The source-level fact survives: `packEvidenceCards` still reports `object-state: N item(s) not shown (evidence budget)`. Before the ranker, object-state was registered last and its cards were the FIRST to be truncated, so this is strictly better, not a new loss.
- **Each vector source embeds the query itself.** `searchContext` calls every registered source, and both vector adapters invoke a primitive that embeds the query, so one boundary read costs one embedding call per vector source. #426 landed the first real caller but not the shared-embedding seam, so one `system.search_context` call still pays two embedding calls; the seam is deferred to a focused follow-up, and the boundary and `ContextSource` contract stay unchanged so it can land without churn. The direct combined caller (`skill-documentation-context`) embeds once and passes `queryEmbedding` to the primitives itself and is unaffected.
- **An `error` report carries provider text.** `toMessage(error)` may name a provider or carry provider-shaped noise; the boundary sanitizes it and `packEvidenceCards` bounds it with `sanitizeErrorMessage` before it reaches the model, but the model-facing tool (#426) still decides whether to surface it at all.
- **The `unavailable` selection branch has run only under test.** No production manifest declares `availability: "unavailable"` today — the three built-ins all declare `available` — so the exclusion path is exercised by the manifest tests, never by a real boot. A misdeclared manifest still shows up as a visible `skipped` line rather than a silent loss, but the branch has no production proof yet.

- **The expansion phase has no provider behind it.** No registered source declares `expand`, so every route table is empty on a real boot and the phase returns the evidence untouched at the cost of one map build. A test expander proves routing, replacement, the shared-handle fold, the cap, and each failure path, but nothing has yet run against a provider's latency, its rate limit, or a record it no longer holds. #428 registers the first real expander and is where those readings arrive.
- **A handle can be born unroutable, and nothing reports it.** `expansionKinds` is an open string space that the card minting a handle and the manifest claiming it must agree on. No check joins the two ends: a card can mint `kind: "github_pull_request"` while every manifest spells it `github_pr`, and the phase simply passes that card over and leaves it exactly as it was. The failure is invisible by design — an unrouted handle is indistinguishable from a card that carries no handle at all — so it shows up as evidence that is quietly never refreshed rather than as an error. Closing it needs either a shared kind enum, which would freeze the vocabulary an MCP source needs open, or a boot-time reconciliation that no source list can supply while the kinds are minted per card.
- **All three built-in sources mint handles that name THEMSELVES, and none declares `expand`.** `documents`, `memory`, and `object-state` each stamp their own id into the handle's `sourceId` and declare no expansion kinds, so today every handle in a production read is unrouted. This is the expected state before #428, and it means the `expansion-only` skip reason, the report replacement, and the `evidenceCount` transfer are all exercised by tests alone — the same "branch has run only under test" gap the `unavailable` selection branch carries.
- **The `evidenceCount` transfer makes one card's provenance move without its status.** A source whose every card a refresh replaced still reports `ok` with `evidenceCount: 0`, which reads like a source that answered and had everything truncated away. The status is the honest one — the source DID answer — but a reader comparing `ok` against the packed output has to know the phase exists to explain the zero. `ContextSearchResult.ranking` is the recovery path, because it still names the card the refresh replaced.
- **Two sources declaring one handle kind resolve by registration order, silently.** `expansionRoutes` keeps the first registered source and drops the second, with no report and no boot error. Registration order is a composition-root fact, so the route is stable and reproducible, but a second expander added for a kind another source already claimed goes dead without saying so. A boot-time conflict throw was not taken: it would make an MCP source that declares a common kind able to fail a boot, which is the opposite of the degradation rule.
