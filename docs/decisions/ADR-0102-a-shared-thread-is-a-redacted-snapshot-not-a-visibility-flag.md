# ADR-0102 — A shared thread is a redacted snapshot behind a capability URL, not a visibility flag on the live thread

**Decision.** Sharing a chat thread writes a new `shared_threads` row that holds a frozen, redacted copy of the transcript and its finished artifacts. It does not set a flag on `chat_threads`. The row's `url_slug` is the whole read capability: `GET /api/shared/:urlSlug` needs no session, and `/c/$slug` renders the row and nothing else. Revoking deletes the row.

The owner surface is the chat header. `Share` opens a dialog that mints or reuses a link and lists every live share with a Revoke action. The neighbouring `...` menu holds Rename, Pin, Delete, Copy as Markdown, thread usage, and the model and autonomy defaults. Both controls shipped as decoration in the first commit and did nothing until now.

Sub-decisions:

1. **A snapshot, not a flag.** A visibility flag publishes every future turn the moment it lands, including every tool result inside it. The owner consents once and keeps consenting without knowing it. A snapshot binds the consent to what was on screen. A later turn, a later rename, and a later artifact edit change nothing a visitor sees.
2. **The slug is the capability, at 80 bits.** There is no token column, no `visibility` enum, and no per-visitor grant. The slug is therefore the whole access control, so it carries a 16-character suffix over a 32-symbol alphabet. Dimension uses 6 characters (about 30 bits), which an attacker can walk; that width is not copied. The title half of the slug is cosmetic and truncated.
3. **Redaction runs at write time.** `buildSnapshot` strips the dropped fields before the `INSERT`, so the row never holds them. This is the control that holds under a later bug: a read path cannot leak a column that does not exist. The publication shapes in `@alfred/contracts` are narrower types than the synced rows, so widening one is a visible edit to a documented schema rather than a quiet field addition.
4. **A tool call publishes its name and its outcome, never its contents.** `argsPreview` and `resultPreview` are dropped. On this product those two fields routinely hold raw Gmail bodies, calendar attendee lists, Drive file contents, and GitHub issue text — the private material the assistant exists to read. A visitor sees that Alfred searched email, not what it found. Also dropped: `usage` (the owner's token spend and cost), `errorKind` (Alfred's internal failure taxonomy), `connectNudge` (a repair affordance a visitor cannot act on, which also names the owner's broken integrations), and the internal `userId` / `threadId` / `runId` identifiers, which would let an outsider correlate several shared threads back to one account.
5. **Reasoning is published.** It is the model's own thinking, the owner already sees it in a collapsible section, and a share that hides it misrepresents how the answer was reached. It is also the field most likely to quote private context word for word, so the share dialog says in plain words that reasoning is published.
6. **A failed turn publishes as failed.** `status` survives the redaction even though `errorKind` does not. A transcript that silently drops its failures is a doctored transcript.
7. **Only `complete` artifacts publish, their bodies are copied, and the published body union is narrow.** A `generating` body is half-written and an `error` body is a failure the owner never chose to show, so the published shape has no `status` field at all. Dimension's public page re-reads artifact bodies live by id, so a later edit rewrites an already-shared page; here the body is copied at publish time and the read never joins back to `artifacts`. `sharedThreadArtifactBodySchema` has exactly two variants. A `document` publishes its markdown, because the owner authored it as prose. A `pages` artifact publishes a COUNT and no HTML — not because the HTML would run (`ArtifactPageFrame` already renders it in a `sandbox=""` iframe, which blocks scripts), but because a page body is ASSEMBLED FROM TOOL RESULTS. Inlining it would restate the mail, calendar, and file content that D4 just removed from the same thread, through a second door. An `external_file` body has no variant at all: it is a pointer into the owner's Drive — a file id, a preview URL, a file name — with no reader on a public page. An artifact whose body fits neither variant is DROPPED from the snapshot rather than published with an empty body, so the row cannot hold a field this union cannot express.
8. **Publishing is idempotent, and a unique index is what makes it so.** `snapshot_digest` is the SHA-256 of the canonical published value, and `(source_thread_id, snapshot_digest)` is UNIQUE. Publishing computes the digest, reads by it, then inserts with `onConflictDoNothing` and re-reads on a miss. This is not tidiness: every mint is a second live public URL the owner must remember to revoke separately, so a Share button that minted per click would scatter copies of a private conversation. The rule lives in the index and not in a read-then-insert check, because two concurrent Share clicks both pass a check and only one can pass an index. Hashing the whole value rather than comparing three proxies — last message id, message count, artifact count — also closes the cases those proxies miss: a rename, an edited artifact body, and a retried turn all leave the counts alone while changing what a visitor reads. Once the thread moves on, the digest changes, the next click mints a new share, and the old URL keeps serving its own older snapshot.
9. **Revoke is a hard delete.** There is no `revoked_at` column. A revoked share must stop existing rather than become a row a later query forgets to filter, and deleting it removes the snapshot bytes too. Both foreign keys cascade, so deleting the thread or the user revokes every share of it. Dimension has the delete verb on its server and no web call site for it; the revoke UI is the reason this ADR exists rather than a copy.
10. **The public route is a separate Elysia instance, under `/api/shared`.** An `auth: true` guard applies to every route declared in its block, so a public route written as a `{ auth: false }` exception makes the next route added beside it inherit the wrong side of the line. Two instances make the split structural. The public instance is mounted at `/api/shared` and not at `/api`, so it owns one narrow prefix rather than the namespace every authed route also lives in — an unauthenticated instance that owns `/api` answers any path an authed route has not claimed. A missing slug answers 404 with no detail — "revoked" and "never existed" must read the same, or a prober learns whether a guessed slug was ever real.
11. **The public page is a second view of the chat feature, and lives in `-chat/`.** It reuses `MessageBubble` so a published transcript keeps the markdown, reasoning panel, and tool trail the owner saw rather than drifting into a second renderer. The folder is a module boundary; the trust boundary is what the file mounts — no `AppShell`, no Replicache, no session read. The route declares `staticData: { publicRoute: true }`, which is what makes it reachable: `AppShell` reads that flag to skip both the chrome and the signed-out redirect to `/login`. The flag replaced a hardcoded list of pathnames inside `AppShell`, which failed in the direction nobody tests — a public route omitted from the list redirects its only audience away, and a signed-in developer, who is never redirected, sees the wrong chrome and reads it as cosmetic. Making `MessageBubble` safe to mount signed out required a fix: `ConnectNudgeRows` called a credential query above its empty guard, so every bubble on the public page asked an authenticated endpoint who the visitor was. The query now lives in a child that only mounts when a message carries a bounce, which a published message never does.
12. **The owner's list is a summary, not a body.** `listThreadShares` returns slug, title, message count, artifact count, and date. The dialog needs to name the link, date it, preview it, and revoke it; it does not need the snapshot. The two counts are STORED columns (`message_count`, `artifact_count`) written at publish time, not `jsonb_array_length` over the body: the list is read every time the dialog opens, and counting through the body would load every published transcript to print two numbers.
13. **The public page renders alt text, never a remote image.** A transcript can contain `![](https://tracker/…)`, written by the model or pasted by the owner. On the owner's own screen that is one request they chose to make; on a published page it is one request per VISITOR, from the visitor's IP, to a host nobody vetted. The snapshot cannot strip the markdown — the text is the conversation — so the renderer refuses instead. A `PublishedTranscript` context puts every markdown surface under `/c/$slug` into alt-text mode, and its default is "render", so a surface added later is safe only inside the provider: the omission is visible rather than silent.
14. **The page is `noindex`, in three places.** A crawler that indexes `/c/$slug` removes the need to guess an 80-bit slug, which is the whole access control (D2). `robots.txt`, an `X-Robots-Tag` header in the Caddyfile, and the route `head` each state the rule, because each is what a different client reads and any one of them alone is a single point of failure.
15. **The public read is rate-limited, and the limiter fails OPEN.** The counter is a cost control, not an access control — the slug is the access control. A Redis outage must therefore not break a published link, so a limiter that cannot reach its store admits the request. `x-forwarded-for` is read RIGHT to LEFT; reading from the left lets any caller mint a fresh bucket per request by prepending an address. The snapshot also refuses above `MAX_SNAPSHOT_BYTES`, which bounds the row alongside the 500-message ceiling.
16. **An attachment publishes as a count.** The bytes sit behind the owner's auth-gated content proxy and a visitor cannot fetch them, so the snapshot carries `attachmentCount` per turn and no files. Publishing the count is what keeps the transcript honest, for the same reason D6 keeps a failed turn: a turn that carried three screenshots would otherwise read as a bare sentence, and the reply to it would read as a non sequitur.

**Extends ADR-0089** (assistant module boundaries) for the new `sharing` module. **Relates to ADR-0075** (the artifact engine) for what an artifact publishes.

---

## Why a snapshot rather than a visibility flag

A flag is the cheaper build and the wrong consent model. The owner reads the thread, decides it is safe to show, and flips the flag. Every turn after that publishes itself. On an assistant whose turns embed mail bodies and calendar entries, the gap between "what I approved" and "what is public" widens with use, and nothing tells the owner it has.

A snapshot costs one copy of the transcript per share and removes the gap entirely. The cost is bounded — sharing refuses above 500 messages rather than minting a huge row — and it buys a second property for free: the redaction has a single place to run, at write time, where it is one function on one path rather than a filter every future read must remember.

## Why the previews are dropped rather than truncated

Truncation is the tempting middle: keep the first line of a tool result so the trail reads richer. It does not survive the threat model. The first line of a Gmail result is the subject and sender of a private mail. The first line of a calendar read is who the owner is meeting. There is no prefix length at which those become safe, because the leak is in the beginning of the value, not in its tail.

Showing the tool name and its outcome keeps what a reader actually wants from a trail — that Alfred did the work, and whether the work succeeded — and none of what makes it dangerous.

## What this deliberately does not build

Dimension's social share buttons, email share, recent-contacts list, OG card generation, and its "fork this thread into my account" `/copy` path. The user chose the link plus revoke. The route `head` also carries no thread title: titles are user-authored and can quote private context, and route `head` output is what a link preview scrapes, so the tab and the preview stay generic and the title renders only inside the page once the snapshot has loaded.
