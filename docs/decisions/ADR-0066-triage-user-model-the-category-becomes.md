# ADR-0066 — Triage user-model: the category becomes significance-weighted (reverses ADR-0059); envelope + user-role + standing-instruction signals make the cheap model see who the user is

**Decision.** Rebuild triage classification around a **user-model**. The classifier today reasons about _what a mail says_, blind to **who the user is**, **whether the mail is even theirs to act on**, and **how much the sender/stakes matter to them** — so it over-tags (#210/#218). The load-bearing move: **the category becomes significance-weighted.** Routine / cold-sender / broadcast actionable noise → `fyi`; `urgent`/`action_needed`/`awaiting_reply` are reserved for items that carry a **real stake** or come from a **significant / role-relevant** source. The category is no longer a taxonomically-honest description of the mail; it is a **useful, significance-weighted signal for the user** — the right trade for a single-user personal assistant.

**The pivot — and what it reverses.** ADR-0059 explicitly _rejected_ letting significance demote the category ("a cold ask is still an honest `awaiting_reply`; significance only gates the todo"), and ADR-0064/#210 then built priority as a **separate** presentation axis (demote at the briefing lane + rail, never the category) precisely to preserve ADR-0048's immutable-honest-label invariant. This ADR **reverses that**: significance is folded **into the category decision itself**. When the user wakes and sees `action_needed`, it must _mean_ something — a dimmed-but-still-`action_needed` chip on a routine PR-merge ask is exactly the noise they're drowning in. ADR-0064's separate attention axis is **subsumed** (its recurrence-decay may survive as a presentation nicety; its significance-weighting moves into the category).

**What stays invariant.** Same **10-label set** (`urgent, action_needed, follow_up, awaiting_reply, meeting, fyi, done, payment, newsletter, marketing`), **no new column**, **no two-axis content×lifecycle state machine** (that mirrors the dimension reference's full machinery — overkill at single-user scale; the _pattern_ is worth more than the _package_). The **security floor** (ADR-0048/0060) remains absolute: an exposed secret stays `urgent` even under a "mute this sender" instruction; users may up- or down-rank everything _else_. One immutable tag per thread, re-evaluated on reply (ADR-0051) — significance is read at classify time and does not silently re-stamp old rows (that is what the single backfill is for).

**`awaiting_reply` stays inbound + significance-gated.** It is "a sender who _deserves_ a reply is waiting on you" — cold/weak/no-history inbound ask → `fyi`; significant/two-way → `awaiting_reply`/`action_needed`. **Bare outbound sent-mail is NOT surfaced** as a demanding category (the dimension recon confirms it only tagged threads with an actual reply). The earlier "directional `awaiting_reply` = user-sent-and-waiting" reading was a **handoff misread, corrected** — there is no outbound-waiting redefinition.

**The demotion floor (reused verbatim from todo rubric 16b, promoted from gating the todo to gating the category).** Significance demotes **person-driven demand** (asks, reply-requests, connection requests). Significance **never** demotes **real intrinsic-stake demand** — money owed (`payment`), a _genuine_ deadline, loss of access, a security exposure (`urgent`), a commitment the user made; a cold sender's overdue invoice is still `payment`. **Manufactured stakes do not shield** — sender-imposed "respond by EOD," marketing scarcity, gamified/ceremonial urgency is not a real deadline (reuse the existing `manufactured:`/11a distinction) and does not protect a low-significance item from demotion. Everything is **overridable** by a standing instruction.

**Three new deterministic signals (ADR-0051 "make the cheap model smart" — pure observations assembled pre-model; the default stays LLM-judged but constrained).**

1. **Envelope / audience.** Computed from `to`/`cc`/headers (already persisted: `to`/`cc` in `documents.metadata`, full headers in `documents.raw.payload.headers`) vs the user's **known addresses** = connected Google account labels (`integration_credentials.accountLabel`) plus ADR-0067 identity projections when available. Emits `recipientPosition` (direct / cc'd / not-listed = forwarded/distribution), `audienceSize`, `isDistributionList`. **Two consumers, treated differently:** (a) **category — soft signal** ("an action on mail you're not directly addressed on is rarely your personal `action_needed` → lean `fyi` unless a real stake, a relevant user role, or a standing instruction says otherwise"; soft because a forwarded mail _can_ be yours); (b) **entity projection — HARD gate delegated to ADR-0067**: a distribution alias / list sender (`engineering@…`, `'X' via Engineering`, `List-Id` present, no real personal address) projects as `group`/`service`, never `person`, and is never person-significance-scored. This fixes the live bug — `'Anthropic' via Engineering` is currently the **top-scored "person" on prod (0.72)**, corrupting every significance-weighted decision. Misjudging a forwarded mail's category is recoverable + overridable; personifying a distribution alias as the #1 contact is not.

2. **The "You (the user)" block.** Triage reads **zero** user-context today (rule 16a's ownership gate has only name+email). Add a **bounded** role/ownership observation — role/title, ownership/responsibility domains ("owns: baserow-middleware, autosched; backend lead"), same-org signal — assembled from ADR-0067 projections via `getUserContext()` (confirmed facts only), `bio_summary`, and subject-bound user/entity facts. Powers (a) significance _relative to the user's role_ and (b) **role-based escalation**: a broadcast "who can fix the baserow outage?" _is_ `action_needed` if the user owns baserow, even sent to `engineering@`. Kept terse (same discipline as the Sender-relationship line) given the cheap-model cost — a role+ownership summary, not the full bio/dossier.

3. **Standing instructions (ADR-0060, now built + extended to the category).** The override that makes a universal rubric's inevitable holes a non-problem: the rubric is a sane default; the user's stated preferences flip it. The user says it in chat ("engineering group sessions are `fyi` for me", "PR-merge asks on the alfred repo are `action_needed`"); the **boss recognizes** it and writes an ADR-0067 `source='user'|'alfred_chat'` observation. The ADR-0060 `user_facts` row (`key=standing_instruction`, optional `target`, optional `enforcement`) is the projection consumed at classify, not a parallel authority. Applied prose-first, with a deterministic carve-out for `enforcement` hard guarantees, resolved against the entity-graph + calendar (where the "graph backend" earns its place — context for _interpreting_ the directive, not a rigid rule table). Precedence: ADR-0067 rank-then-recency across sources; specificity-then-recency among projected matching instructions; security floor un-down-rankable. Manageable in `/settings`.

**The user-model stays current (auto-update loop, via ADR-0067).** `user_facts` already carries `confidence`, `status` ∈ {proposed, confirmed}, `validUntil`; `getUserContext()` reads `confirmed`-only; `standing-instructions`/`rejected`/`preferences` modules exist. ADR-0067 changes the source of those facts from a triage-local mail extractor to replayable observations: integration observations propose role/ownership facts; chat/user-correction observations are high-precedence; **high confidence** (strong explicit signal / corroboration) → `confirmed` → feeds the "You" block; **low confidence** → `proposed` → **not** consumed; **corroboration** by later observations promotes `proposed`→`confirmed`; role changes use `validUntil`. Surfaced via a `/settings` "Learned about you — confirm/dismiss" queue + a one-line briefing mention for auto-confirmed facts. No per-fact chat interruption.

**Single sequenced backfill (no repeated vacuums).** The tags are re-written **once**, after context exists: ship ADR-0067 shadow projection → validate identities/kinds/significance/facts → read-only `dry-run-triage-recategorize-committed.js` (review the old→new transition matrix and false-demotion samples) → one committing `backfill-triage-committed.js --commit` (re-classify with full context + new rubric, re-stamping significance bands). Rule 8a (social invites → `fyi`, PR #252) is the shipped first slice and is consistent with the pre-0067 fast-relief rule.

**Why.** Every prior fix treated a symptom — a rubric patch per leak, a presentation-layer dimmer (#210) that still showed `action_needed` on the chip. The disease is that the classifier has no model of the user. Folding significance into the category (not a parallel axis) is what finally makes `action_needed`/`urgent` trustworthy; the envelope + "You" signals are the cheap deterministic context (ADR-0051) that lets the cheap model judge "is this mine?"; standing instructions are the escape valve that makes a universal rubric's holes irrelevant — the user states the exception once and it sticks. The trade — surrendering "the category is a taxonomically honest label" for "the category is a useful, user-weighted signal" — is correct for a single user who reads the label as "what should I deal with," not "what taxonomically is this."

**Alternatives.** (a) **Keep ADR-0064's separate attention axis** (honest category + dimmed rail) — rejected: the chip still reads `action_needed` on routine asks, which is exactly the noise; and the dimension recon shows even dimension's `action_needed` was noisy (its edge was context-driven _surfacing_, which we can't fully match and whose tagging output we wouldn't want to copy). (b) **Two-axis content×lifecycle state machine** (dimension's model) — rejected: dimension-package mirroring; the 10-label set + significance-weighting carries the value at single-user scale, and a second column breaks ADR-0048's one-tag invariant. (c) **Directional/outbound `awaiting_reply`** — rejected: handoff misread; dimension didn't tag bare sent-mail. (d) **Notification / quiet-hours gating** for the "2 AM" complaint — out of scope: that complaint was _category_ not timing ("I can be asleep"), and tagging is already real-time (`ingest→tag` ≈ 0 on prod — no latency bug). (e) **Pure deterministic rules** for the default — rejected: free-text email can't be classified by rules alone; determinism lives in the _signals that constrain_ the LLM, with user overrides on top ("good deterministic defaults, flexible override"). (f) **Reading dimension's source** to copy its logic — explicitly off-limits (Yash's call; it's his build + a portfolio artifact); recon from the labeled inbox only.

**Parked.** Activity-mined ownership (v1 sources user-context from `user_facts`/`bio_summary`/team-graph). ADR-0064's recurrence-decay as a presentation nicety (revisit whether it survives the category fold). Notification/proactive surfacing. PDF/scanned-doc fidelity is unrelated (ADR-0065).

**Open (decide during build).** The significance cutoff for "deserves a reply" (reuse the `STRONG_AT 0.66`/`MODERATE_AT 0.33` buckets?). How terse the "You" block can be before role-escalation under-serves. Confidence thresholds for auto-`confirmed` vs `proposed` and the corroboration count for promotion. Whether `follow_up` survives as a distinct label under significance-weighting or collapses. Eval coverage for the significance-weighted category + envelope cases (extend `triage-classify.eval.ts`). **Superseded foundation (2026-06-23).** This ADR's entity-cleanup pieces — the distribution-list HARD gate, the polluted-entity purge, the "You"-block inputs, and the single backfill — are **re-scoped to consume the multi-source user-model substrate (ADR-0067)** rather than being built independently on the email-only graph. The dist-list gate falls out of ADR-0067's `kind` taxonomy (`group`/`service` are never person-scored); the "You" block reads `entity_identities` + subject-bound facts; one shadow-build backfill serves both.

**Release correction (2026-06-23 review).** Default to **waiting for ADR-0067 P5** before shipping this ADR's significance-weighted category fold. The legacy graph is known polluted (`engineering@`/service/repo rows scored as people), so folding its sender significance into durable categories risks a second backfill and bad demotions. Pre-0067 relief is limited to graph-independent prompt/eval hardening (`rule 8a`, rationale grounding, read-only recategorize dry-runs). The biggest corruption fix still lands earlier at **ADR-0067 P1**: `engineering@oliv.ai` / `'Anthropic' via Engineering` becomes `group` and stops being person-scored independent of the category rewrite.
