# ADR-0077 — Interactive-chat tier table and boss charter: Auto on Sonnet 4.6, Deep on Opus 4.8 (BUILT — #312; amended 2026-07-02)

**Original decision (2026-06-28; superseded by the 2026-07-02 amendment below).** `getChatModel("standard")` — the **Auto** chat tier, the everyday conversational driver and ~87% of LLM spend — moved from Claude Sonnet 4.6 to **Claude Haiku 4.5** (`claude-haiku-4-5-20251001`). The **Deep** tier stayed on **Opus 4.8**: the heavy, expensive model was _reserved_ for the hard, multi-step turns (and the fan-out boss-worker harness) where the cost buys real reasoning. Both tiers kept their Gemini 2.5 Pro `withFallback` degrade. Because Haiku 4.5 hard-400s on adaptive thinking _and_ the `effort` param (both Sonnet-4.6+/Opus-only), `getChatProviderOptions("standard")` sent an **empty** anthropic provider block — sending either would, via `withFallback`'s switch-on-4xx, silently drop every Auto turn onto Gemini (the #224 class of bug). Deep kept `thinking:{adaptive}` + `effort:"high"`.

**Original why.** A browser-replay adjudication (Sonnet 4.6 vs Gemini 2.5/3.5-flash vs Haiku 4.5, real recorded dev chats replayed in the live app, costs recomputed from Langfuse token counts) found Haiku the only candidate that wins on **both** cost and quality. It is ~3× cheaper per token than Sonnet ($1/$5 vs $3/$15) and the saving actually _lands_ — unlike Gemini 3.5-flash, which passed quality but cost _more_ in practice (2.6×/5.3× token bloat → 1.56× full-price regression) and needed a tool-name shim. Same-provider means Haiku keeps the #223 prompt cache (same tokenizer, ~90% warm-input discount) and the dotted-tool-name handling, so there is no orchestration tax. On tool-heavy chat Haiku matched Sonnet's trajectory; its one observed weakness — under-acting on implicit agentic lookups (asking the user for a sender address instead of searching Gmail) — was an _underspecified prompt_ Sonnet's stronger inference had been masking, not a hard capability ceiling: the search-before-ask prompt hardening (#312) closed it, verified live (the boss now runs `gmail.search` → `system.remember` → `system.resolve_todo` itself), and a `sender-suppression-grounding` eval pins it against regression. Reserving Opus for Deep kept the capability ceiling available exactly where users opt into it, while the default path got faster and ~3× cheaper.

**Original alternatives.** (a) **Keep Sonnet on Auto** — rejected at the time: pays a 3× premium for quality the adjudication showed Haiku matches on real chat traffic; the cost lever on the 87%-of-spend line is too large to leave. (b) **Gemini 2.5-flash or 3.5-flash on Auto** — rejected: 2.5-flash failed quality (mis-orchestrated, punted), 3.5-flash was a _cost regression_ despite a lower sticker price, and both need the `.`→`__` tool-name shim and forfeit the prompt cache (`project_gemini_chat_boss_adjudication`). (c) **A capability map driving the thinking/effort block off the resolved model id** — _deferred to #313_: the right long-term shape (so a future tier remap can't reintroduce an unsupported param), but for a fixed two-tier mapping a `tier === "deep"` branch is correct and minimal; the TODO is in the code. (d) **Sonnet as a middle tier between Haiku and Opus** — rejected then: the chat UI exposes only Auto/Deep, so a third tier has no surface; revisit with the #249 model-router. (e) **Block on a wider eval corpus before flipping** — declined: the adjudication is n=2 chats, but the search-before-ask eval + the non-gating nightly grounding-evals run (#312) give ongoing regression coverage, and the fallback + per-thread provider stickiness bound the blast radius of a bad turn; widening the corpus continues in the eval lane rather than gating the swap.

**Original cross-ref.** Consumed the search-before-ask prompt hardening + `sender-suppression-grounding` eval + nightly `grounding-evals` workflow, all shipped in #312, as the safety net that made the swap defensible. The `getChatProviderOptions` tier→capability branch is the seam ADR-0053/#313's per-model capability map absorbed in ADR-0078. Ties to the #249 model-router (which may later make Auto self-route across tiers rather than pin to a fixed model). Cost context: `project_llm_cost_shape` (Anthropic = 96% of spend, Sonnet = 87%).

**Amendment (2026-07-02) — Haiku Auto reversed; boss prompt rulebook replaced with a capability+judgment charter.** A production chat thread, **"Sakshi Jindal Contact Info"**, disproved the #312 safety story. Across four turns on 2026-07-02, including a final **Deep / Opus 4.8 high-effort** turn, the user repeatedly asked to "find more" about a person and the boss made **zero** `system.web_search` calls. It kept returning to Alfred memory and Gmail because the prompt's people/name rules routed inward and never described the live web as a source for public person/company background. Therefore the failure is not just a Haiku model-quality issue and not solved by a bigger model alone; it is a steering-shape issue: prompt patches accreted into a rulebook that can suppress available capabilities.

Current decision: `standard` / **Auto** runs on **Claude Sonnet 4.6** with adaptive `effort:"medium"` and Gemini 3.5 Flash fallback. `deep` stays **Claude Opus 4.8** with adaptive `effort:"high"` and the same fallback. Sonnet 5 is explicitly rejected for Auto because, as of the pricing check that drove this amendment, it priced above Opus 4.8; Sonnet 4.6 is already in the registry, reasoning-capable, and matches `getBossModel()` / `getSubAgentModel()`, so the chat boss and the sub-agents it delegates to now share a consistent floor. This reverses the 2026-06-28 Haiku cost downgrade for interactive chat only; cheap/background classifiers and extraction defaults are unaffected.

The boss system prompt is also changed from scenario patches to a charter: mission, capability menu (memory, connected services, live web, sub-agents), source-ladder judgment, prefer-acting-to-asking, repeated-ask escalation to a new source, honest wall-hitting behavior, write-gating, no false success, no internal leakage, artifact delivery, exact URL linking, and concise narration. The prior specific patches (`people -> read_user_context`, Gmail/GitHub name-resolution walkthroughs, LOC/PR examples) are removed because they are the class of brittle routing rules that caused the failure. Validation moves to a judgment eval group (`boss-judgment.eval.ts`) that asserts the source class reached: repeated "more" asks and public/current questions must hit web or delegate to a sub-agent, calendar asks must not over-search, and hidden richer-source cases (for example ClickUp notifications in Gmail with no ClickUp integration) must be named honestly rather than thinly summarized.

Escalation stays on two separate axes. **Source/breadth escalation** is automatic and model-judged: climb the memory -> connected accounts -> web ladder, and delegate open-ended research to a sub-agent. **Model escalation** remains manual via the Deep picker. Auto-escalating a repeated/hard turn to Deep is deferred because it reintroduces turn-level mechanism before proving the charter plus Sonnet 4.6 floor is insufficient.

**Amendment (2026-07-10) — Gemini 2.5 Pro fallback retired for Gemini 3.5 Flash.** Boss, sub-agent, Auto, and Deep provider-failure fallbacks now use `gemini-3.5-flash`. Artificial Analysis measures Gemini 3.5 Flash at 45 (medium) / 50 (high), about 187–194 output tokens/s, and $1.50/$9 input/output per MTok, versus Gemini 2.5 Pro at 26, about 150 tokens/s, and $1.25/$10. The change is not justified by the headline high score alone: the chat fallback receives the same tier effort as its primary (`medium` for Auto, `high` for Deep), mapped to Google `thinkingConfig.thinkingLevel`; boss/sub-agent fallbacks retain the provider default because those workflows do not send a reasoning block today. Gemini 3.5's prior Alfred replay showed 2.6× input and 5.3× output-token expansion, so lower list output price is not assumed to mean lower cost per completed task. Served-model token counts, turns, wall time, and cost remain the production adjudication; 3.5 Flash is selected here because it materially raises fallback capability and throughput while slightly lowering the 7:2:1 cache/input/output blended list rate (~$1.31 vs ~$1.34), not as a primary-model cost optimization.

**Amendment (2026-08-28) — Gemini 3.5 Flash fallback temporarily reverted to Gemini 2.5 Flash for Cloudflare AI Gateway.** Live probes via the Cloudflare gateway (`gateway.ai.cloudflare.com/v1/{account}/{gateway}/google-ai-studio`) and via the direct Google API both return **403 unregistered caller** for `gemini-3.5-flash` (model id not yet registered for the caller's project/gateway). Under `withFallback`, a non-retryable 403 on the fallback leg is not retried — it hard-fails the turn instead of degrading. Boss, subAgent, standard, and deep therefore temporarily pin their fallback to `gemini-2.5-flash` (the highest available Google model that succeeds through both surfaces). The `gemini-3.5-flash` registry entry and pricing remain reserved; reinstate the fallback by reverting `packages/ai/src/provider.ts` and removing this paragraph once the probe succeeds through the gateway.
