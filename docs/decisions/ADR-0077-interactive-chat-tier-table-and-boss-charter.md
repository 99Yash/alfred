# ADR-0077 — Interactive-chat tier table and boss charter: Auto on Sonnet 4.6, Deep on Opus 4.8 (BUILT — #312; amended 2026-07-02)

**Original decision (2026-06-28; superseded by the 2026-07-02 amendment below).** `getChatModel("standard")` — the **Auto** chat tier, the everyday conversational driver and ~87% of LLM spend — moved from Claude Sonnet 4.6 to **Claude Haiku 4.5** (`claude-haiku-4-5-20251001`). The **Deep** tier stayed on **Opus 4.8**: the heavy, expensive model was _reserved_ for the hard, multi-step turns (and the fan-out boss-worker harness) where the cost buys real reasoning. Both tiers kept their Gemini 2.5 Pro `withFallback` degrade. Because Haiku 4.5 hard-400s on adaptive thinking _and_ the `effort` param (both Sonnet-4.6+/Opus-only), `getChatProviderOptions("standard")` sent an **empty** anthropic provider block — sending either would, via `withFallback`'s switch-on-4xx, silently drop every Auto turn onto Gemini (the #224 class of bug). Deep kept `thinking:{adaptive}` + `effort:"high"`.

**Original why.** A browser-replay adjudication (Sonnet 4.6 vs Gemini 2.5/3.5-flash vs Haiku 4.5, real recorded dev chats replayed in the live app, costs recomputed from Langfuse token counts) found Haiku the only candidate that wins on **both** cost and quality. It is ~3× cheaper per token than Sonnet ($1/$5 vs $3/$15) and the saving actually _lands_ — unlike Gemini 3.5-flash, which passed quality but cost _more_ in practice (2.6×/5.3× token bloat → 1.56× full-price regression) and needed a tool-name shim. Same-provider means Haiku keeps the #223 prompt cache (same tokenizer, ~90% warm-input discount) and the dotted-tool-name handling, so there is no orchestration tax. On tool-heavy chat Haiku matched Sonnet's trajectory; its one observed weakness — under-acting on implicit agentic lookups (asking the user for a sender address instead of searching Gmail) — was an _underspecified prompt_ Sonnet's stronger inference had been masking, not a hard capability ceiling: the search-before-ask prompt hardening (#312) closed it, verified live (the boss now runs `gmail.search` → `system.remember` → `system.resolve_todo` itself), and a `sender-suppression-grounding` eval pins it against regression. Reserving Opus for Deep kept the capability ceiling available exactly where users opt into it, while the default path got faster and ~3× cheaper.

**Original alternatives.** (a) **Keep Sonnet on Auto** — rejected at the time: pays a 3× premium for quality the adjudication showed Haiku matches on real chat traffic; the cost lever on the 87%-of-spend line is too large to leave. (b) **Gemini 2.5-flash or 3.5-flash on Auto** — rejected: 2.5-flash failed quality (mis-orchestrated, punted), 3.5-flash was a _cost regression_ despite a lower sticker price, and both need the `.`→`__` tool-name shim and forfeit the prompt cache (`project_gemini_chat_boss_adjudication`). (c) **A capability map driving the thinking/effort block off the resolved model id** — _deferred to #313_: the right long-term shape (so a future tier remap can't reintroduce an unsupported param), but for a fixed two-tier mapping a `tier === "deep"` branch is correct and minimal; the TODO is in the code. (d) **Sonnet as a middle tier between Haiku and Opus** — rejected then: the chat UI exposes only Auto/Deep, so a third tier has no surface; revisit with the #249 model-router. (e) **Block on a wider eval corpus before flipping** — declined: the adjudication is n=2 chats, but the search-before-ask eval + the non-gating nightly grounding-evals run (#312) give ongoing regression coverage, and the fallback + per-thread provider stickiness bound the blast radius of a bad turn; widening the corpus continues in the eval lane rather than gating the swap.

**Original cross-ref.** Consumed the search-before-ask prompt hardening + `sender-suppression-grounding` eval + nightly `grounding-evals` workflow, all shipped in #312, as the safety net that made the swap defensible. The `getChatProviderOptions` tier→capability branch is the seam ADR-0053/#313's per-model capability map absorbed in ADR-0078. Ties to the #249 model-router (which may later make Auto self-route across tiers rather than pin to a fixed model). Cost context: `project_llm_cost_shape` (Anthropic = 96% of spend, Sonnet = 87%).

**Amendment (2026-07-02) — Haiku Auto reversed; boss prompt rulebook replaced with a capability+judgment charter.** A production chat thread, **"Sakshi Jindal Contact Info"**, disproved the #312 safety story. Across four turns on 2026-07-02, including a final **Deep / Opus 4.8 high-effort** turn, the user repeatedly asked to "find more" about a person and the boss made **zero** `system.web_search` calls. It kept returning to Alfred memory and Gmail because the prompt's people/name rules routed inward and never described the live web as a source for public person/company background. Therefore the failure is not just a Haiku model-quality issue and not solved by a bigger model alone; it is a steering-shape issue: prompt patches accreted into a rulebook that can suppress available capabilities.

Current decision: `standard` / **Auto** runs on **Claude Sonnet 4.6** with adaptive `effort:"medium"` and Gemini 3.5 Flash fallback. `deep` stays **Claude Opus 4.8** with adaptive `effort:"high"` and the same fallback. Sonnet 5 is explicitly rejected for Auto because, as of the pricing check that drove this amendment, it priced above Opus 4.8; Sonnet 4.6 is already in the registry, reasoning-capable, and matches `getBossModel()` / `getSubAgentModel()`, so the chat boss and the sub-agents it delegates to now share a consistent floor. This reverses the 2026-06-28 Haiku cost downgrade for interactive chat only; cheap/background classifiers and extraction defaults are unaffected.

The boss system prompt is also changed from scenario patches to a charter: mission, capability menu (memory, connected services, live web, sub-agents), source-ladder judgment, prefer-acting-to-asking, repeated-ask escalation to a new source, honest wall-hitting behavior, write-gating, no false success, no internal leakage, artifact delivery, exact URL linking, and concise narration. The prior specific patches (`people -> read_user_context`, Gmail/GitHub name-resolution walkthroughs, LOC/PR examples) are removed because they are the class of brittle routing rules that caused the failure. Validation moves to a judgment eval group (`boss-judgment.eval.ts`) that asserts the source class reached: repeated "more" asks and public/current questions must hit web or delegate to a sub-agent, calendar asks must not over-search, and hidden richer-source cases (for example ClickUp notifications in Gmail with no ClickUp integration) must be named honestly rather than thinly summarized.

Escalation stays on two separate axes. **Source/breadth escalation** is automatic and model-judged: climb the memory -> connected accounts -> web ladder, and delegate open-ended research to a sub-agent. **Model escalation** remains manual via the Deep picker. Auto-escalating a repeated/hard turn to Deep is deferred because it reintroduces turn-level mechanism before proving the charter plus Sonnet 4.6 floor is insufficient.

**Amendment (2026-07-10) — Gemini 2.5 Pro fallback retired for Gemini 3.5 Flash.** Boss, sub-agent, Auto, and Deep provider-failure fallbacks now use `gemini-3.5-flash`. Artificial Analysis measures Gemini 3.5 Flash at 45 (medium) / 50 (high), about 187–194 output tokens/s, and $1.50/$9 input/output per MTok, versus Gemini 2.5 Pro at 26, about 150 tokens/s, and $1.25/$10. The change is not justified by the headline high score alone: the chat fallback receives the same tier effort as its primary (`medium` for Auto, `high` for Deep), mapped to Google `thinkingConfig.thinkingLevel`; boss/sub-agent fallbacks retain the provider default because those workflows do not send a reasoning block today. Gemini 3.5's prior Alfred replay showed 2.6× input and 5.3× output-token expansion, so lower list output price is not assumed to mean lower cost per completed task. Served-model token counts, turns, wall time, and cost remain the production adjudication; 3.5 Flash is selected here because it materially raises fallback capability and throughput while slightly lowering the 7:2:1 cache/input/output blended list rate (~$1.31 vs ~$1.34), not as a primary-model cost optimization.

**Amendment (2026-08-28) — Gemini 3.5 Flash fallback temporarily reverted to Gemini 2.5 Flash for Cloudflare AI Gateway.** Live probes via the Cloudflare gateway (`gateway.ai.cloudflare.com/v1/{account}/{gateway}/google-ai-studio`) and via the direct Google API both return **403 unregistered caller** for `gemini-3.5-flash` (model id not yet registered for the caller's project/gateway). Under `withFallback`, a non-retryable 403 on the fallback leg is not retried — it hard-fails the turn instead of degrading. Boss, subAgent, standard, and deep therefore temporarily pin their fallback to `gemini-2.5-flash` (the highest available Google model that succeeds through both surfaces). The `gemini-3.5-flash` registry entry and pricing remain reserved; reinstate the fallback by reverting `packages/ai/src/provider.ts` and removing this paragraph once the probe succeeds through the gateway.

**Amendment (2026-09-03) — Google fallback moves from Gemini 2.5 Flash to Gemini 3.8 Flash, without a live gateway probe.** Boss, subAgent, cheap, standard, and deep now fall back to `gemini-3.8-flash`; `webSearch` and `compactorFallback` run on it as their only model, and it heads the media-enrichment order. This supersedes the 2026-08-28 paragraph above: that revert waited on a `gemini-3.5-flash` probe, and this amendment retires `gemini-3.5-flash` from the routes instead of reinstating it. The catalog evidence is real — models.dev lists `google/gemini-3.8-flash` (released 2026-09-02) with a 1,048,576-token context window, `low`/`medium`/`high` effort values, text/image/audio/video/PDF input, and $0.75/$3.75 per MTok — and `packages/ai/src/models.ts` matches that entry field for field. **The live-call evidence is absent, and that is the accepted risk of this amendment.** Nobody has called `gemini-3.8-flash` through `gateway.ai.cloudflare.com/v1/{account}/{gateway}/google-ai-studio`, which is exactly the call that returned 403 for `gemini-3.5-flash`. Two consequences follow if the model is unregistered for this gateway: `webSearch` and `compactorFallback` hard-fail (they hold no second model), and every other route loses its degrade leg on a non-retryable 403. Cost also rises where the fallback fires — $0.75/$3.75 against 2.5 Flash's lower rates — and `computeCost` returns 0 for the model until `pnpm --filter @alfred/db db:sync-prices` writes the `model_prices` row from models.dev, so early fallback turns meter as free. Run the gateway probe and the price sync before this reaches production traffic.

**Amendment (2026-09-03b) — Auto moves from Claude Sonnet 4.6 to GPT-5.6 Luna on the GPT-5.6 repricing; Sonnet becomes the fallback.** `standard` — the **Auto** tier and the everyday conversational driver — now runs `chain: ["gpt-5.6-luna", "claude-sonnet-4-6"]` at effort `medium`. `deep` is unchanged (`claude-opus-4-8` + `gemini-3.8-flash`, effort `high`), as are `boss`, `subAgent`, `cheap`, `webSearch`, `compactor`, and `compactorFallback`. This reverses the 2026-07-02 amendment's "Auto runs Claude Sonnet 4.6" for the primary leg only; Sonnet stays in the route as the degrade target, so the fallback leg gets **stronger** than the `gemini-3.8-flash` it replaces there.

**Why now: the price, and only the price, changed.** GPT-5.6 was already qualified and rejected. Issues #470 (Luna as sub-agent worker) and #471 (Sol as boss fallback) were closed **not-planned** on 2026-07-10 after a live paired bake-off, recorded in `.lessons/model-cost-recompute-from-tokens.md`: Sonnet direct 4 calls / 28s / `$0.102`; Luna direct 13 calls / 63s / `$0.105`; Luna boss + Sonnet worker 10 / 97s / `$0.241`; Sol boss + three Luna workers 56 / 143s / `$0.617`. The verdict was cost, latency, and turn count — **never** an authorization or transport blocker (#469 shipped non-default OpenAI language-provider support, and `PROVIDER_SPECS.openai` in `packages/ai/src/provider-adapter.ts` dispatches through `.responses()` today). The closure note invited a reopen "if a cheaper/faster generation warrants a fresh run". A `pnpm db:sync-prices` run on 2026-09-02 supplied the cheaper half: Luna fell **5× uniformly on all four token classes** — input $1.00→$0.20, output $6.00→$1.20, cached read $0.10→$0.02, cache write $1.25→$0.25 per MTok. Anthropic list rates have not moved since 2026-05-22. Blended at Alfred's measured 7:2:1 cache-read/input/output mix, Luna is **$0.174/MTok against Sonnet's $2.31 — a 13.3× discount, where July gave only 2.65×**. Because the cut is uniform, the July Luna-direct trajectory rescales exactly: `$0.105 → $0.021` against Sonnet's unchanged `$0.102`. The measured ~3.25× turn bloat (13 calls vs 4) had precisely eaten the 2.65× discount in July; against 13.3× it leaves roughly 4× of headroom. Auto is ~87% of LLM spend, so this is the largest lever on the cost shape that `project_llm_cost_shape` describes.

**Alternatives rejected.** (a) **GPT-5.6 Sol** — the repricing moved it the *wrong* way in relative terms: at $4/$20 its blended rate is **$3.08, dearer than Sonnet's $2.31**. It can only ever be an Opus alternative, never a Sonnet one. (b) **GPT-5.6 Terra** — blended $1.74, a mere 1.33× discount that cannot pay for losing the Anthropic prompt cache plus a fresh quality qualification. It also has a `model_prices` row but **no `models.ts` registry entry**, so it is not callable at all. (c) **Gemini 3.8 Flash on Auto** — blended $0.578 (4× cheaper) is real, but Gemini as the chat primary is a twice-rejected lever on measured token bloat, and Luna's discount is 3.3× larger again. (d) **Luna as sub-agent worker first**, where latency hurts less than on the interactive path — the safer sequencing, and deliberately declined: the spend concentrates in Auto, not in sub-agents, so worker-first would not move the line this change exists to move.

**Accepted risks, stated because no live Alfred trajectory backs this swap yet.** (1) **Latency and turn count are unaddressed.** Luna measured 63s over 13 calls against Sonnet's 28s over 4. Pricing cannot fix that, and Auto is the interactive path where it is felt most. This is the axis to watch first. (2) **The Anthropic prompt cache is forfeited on the primary leg.** At Alfred's ~20:1 input:output ratio the warm-input discount is a large part of why Sonnet's as-run cost beats its list rate, and `projectAnthropicRequest`'s cache breakpoints no longer apply to Auto's first leg; Luna's own cached-read tier ($0.02) and paid cache writes ($0.25, metered since #468) replace it on different mechanics. The 13.3× blended gap is wide enough to absorb this, but the true figure is as-run, not list. (3) **Effort semantics differ.** `openaiReasoning` sends a flat `reasoningEffort: "medium"` on OpenAI Responses; Anthropic's adaptive thinking block self-sizes trivial turns toward zero. A flat medium may over-think cheap turns — the failure the per-turn effort lever in `project_model_selection_verdicts` already names. (4) **Luna is text/image/PDF only, with a 20 MB inline media cap** against Sonnet's wider modality set; the ADR-0065 degrade-at-ingest path, not model routing, governs attachments, so this is a bound to confirm rather than a known break. (5) **`nativeToolSearch: true` in the Luna registry entry is not honoured** — `PROVIDER_SPECS.openai` declares `nativeToolSearch: false` and `NATIVE_TOOL_LOADING_MODELS` is empty, so tool loading stays on the application protocol. Intentional and unchanged by this amendment.

**Amendment (2026-09-03c) — every OpenAI leg must send `store: false`, because Unified Billing puts Alfred on a Zero Data Retention organization.** The 2026-09-03b Luna swap shipped a latent turn-killing bug, found on live dev traffic within the hour. `providerOptionsForModel` now sends `store: false` on every OpenAI bag (`OPENAI_ZERO_DATA_RETENTION_STORE` in `packages/ai/src/reasoning-policy.ts`), at both `reasoningEffort` and the `disabled` policy.

**The failure.** On the Responses API a reasoning model returns a reasoning item identified by an `rs_…` id. `@ai-sdk/openai@4.0.36` passes `store: openaiOptions?.store ?? true` into its input converter, so with `store` unset the **default is `true`**, and the converter replays a reasoning part carrying an `itemId` as `{ type: "item_reference", id: "rs_…" }` rather than as content. That asks OpenAI to resolve the id from its own store. Alfred reaches OpenAI through Cloudflare AI Gateway Unified Billing, so the upstream organization is Cloudflare's and it is Zero Data Retention — it persists no items. The call returns `invalid_request_error`: "Item with id 'rs_…' not found. Items are not persisted for Zero Data Retention organizations." The error carries `isRetryable: false`, and `withFallback` classifies a 400 as a client bug that must never degrade, so the turn does **not** fall through to the Sonnet leg — it dies, and chat renders "something interrupted this reply".

**Where it fires.** The second leg of a tool loop, which is most useful turns. `api_call_log` shows the shape three times over on dev: `chat-turn:0` succeeds and emits a tool call, `dispatch-tools` runs `agent.web_search`, then `chat-turn:2` fails with the `rs_…` error. Leg 1 alone is always fine, because no reasoning item exists to replay yet.

**The fix, and why it is one line.** `store: false` makes `openai-language-model.ts` add `include: ["reasoning.encrypted_content"]` whenever the model parses as a reasoning model, and the converter then sends the reasoning back as opaque encrypted content that needs no server-side lookup. It also drops any reasoning part that arrived *without* encrypted content instead of emitting a dangling id, so the failure mode is closed from both directions. Nothing is given up: Alfred replays its whole transcript every turn and sets neither `previousResponseId` nor `conversation`, which are the only features that need the store, and OpenAI prompt caching is independent of it. `store: false` also happens to be the posture Alfred's privacy positioning wants, but retention is not why it is here — correctness is.

**Evidence, and its one gap.** A three-arm differential through the live gateway (`references/scratch/probe-luna-zdr-reasoning.ts`, mirroring `AlfredAgent`: `streamText`, `isStepCount(1)`, transcript replayed by hand) reproduced the production error verbatim on `store: true` and completed leg 2 on `store: false` with the reasoning part replayed inline. Two traps make this probe easy to misread, both hit once. A prompt too trivial to force real reasoning yields an empty summary that `ai` core discards, so nothing is replayed and **every arm passes for the wrong reason**. And Cloudflare AI Gateway response caching can serve one arm's answer to another — an identical `rs_…` id across two arms is the tell, and it is what made the `store: unset` arm pass against both the SDK source and production. The gap: the fix has not yet been proved on a real Alfred chat turn with the full tool surface. Confirm by sending one Auto turn that calls a tool and checking that `chat-turn:2` carries no error.

**Verification closed (2026-09-03) — the `store: false` fix holds on a real Alfred turn, and OpenAI prompt caching survives it.** The gap the 2026-09-03c amendment left open is closed. `api_call_log` run `run_ah2ujyysverg` is a live Auto turn that ran **16 model legs** (`chat-turn:0` through `chat-turn:30`) with **zero errors** — a tool loop far past the `chat-turn:2` boundary where all three pre-fix runs died. Two secondary claims in that amendment now have receipts rather than reasoning. Prompt caching is genuinely independent of `store`: leg `chat-turn:20` read 14,728 of its 14,936 input tokens from cache (98.6%), and leg `:18` 14,570 of 14,731 (98.9%), so `store: false` costs Alfred no cache warmth. And the reasoning round trip is intact across all sixteen legs, which it could not be if the SDK were silently dropping reasoning parts for want of encrypted content.

**First as-run cost and latency signal, not yet a verdict.** That 16-leg turn cost **$0.0295** and took **86 seconds** wall (08:12:03.7 → 08:13:29.5). Both numbers point where 2026-09-03b predicted. The cost is small in absolute terms against the $0.987 the earlier 15-call Sonnet thread spent, which is directionally consistent with the 13.3× blended discount — but the two are **different tasks in different threads**, so this is emphatically not the paired replay-diff `.lessons/model-cost-recompute-from-tokens.md` requires, and it must not be quoted as one. The latency and turn-count risk that amendment flagged is meanwhile visible and real: sixteen legs and 86 seconds for a single Auto turn is the token-and-turn bloat the July bake-off measured, now landing on the interactive path. Cost per turn is winning; responsiveness is the axis to watch.

**Amendment (2026-09-03d) — Anthropic leaves both chat tiers; Auto and Deep run GPT-5.6 Luna at `medium` and `max`, with Gemini 3.8 Flash as the fallback.** `standard` (Auto) is now `chain: ["gpt-5.6-luna", "gemini-3.8-flash"]` at effort `medium`. `deep` is now `chain: ["gpt-5.6-luna", "gemini-3.8-flash"]` at effort `max`. `subAgent` is now `chain: ["gpt-5.6-luna", "gemini-3.8-flash"]` at effort `medium`, so a chat turn that delegates runs one vendor end to end. This supersedes the 2026-09-03b chain, which kept Sonnet 4.6 as the Auto fallback, and it replaces Opus 4.8 on Deep. `boss`, `cheap`, `webSearch`, `compactor`, and `compactorFallback` are unchanged; `boss` still runs Sonnet 4.6 because it drives background work only (briefings, triage deepen, cold start, skill compose) and no chat turn reaches it.

**Why.** The 2026-09-03b amendment placed Luna on Auto because of price and kept Sonnet as the degrade leg because it was the proven trajectory. That mix has two costs. A degrade leg at $2.31 blended is 13× the primary, so one fallback turn costs as much as thirteen normal turns. Sonnet on the fallback leg also keeps an Anthropic dependency in the chat path for a leg that fires only on a 429 or a spend cap. The user's decision is that a Luna chat runs on Luna. Deep follows the same logic one step further: the Deep tier is the same model at its strongest effort, so a user who picks Deep pays for more reasoning on the same model rather than for a different vendor. Luna's vocabulary is `none`/`low`/`medium`/`high`/`xhigh`/`max`, so `max` is sent as-is. The Gemini leg receives the tier effort through `clampEffort`, which maps `max` to `high` and `medium` to `medium`, so both bags project without an incompatibility error. Opus 4.8 at $3.85 blended was 22× Luna's rate, and the July chat-edit bake-off already showed Opus does not earn its premium for editing.

**Why sub-agents move too.** The chat boss spawns its workers through the `user-authored-brief` workflow, which reads `route("subAgent")`. Left on Sonnet, a delegating Auto turn would be a Luna boss with Sonnet workers. The July bake-off measured exactly that pairing as the worst shape: 10 calls / 97s / `$0.241` against Sonnet-alone 4 / 28s / `$0.102`. The Luna share of that number is now 5× cheaper; the Sonnet worker share is not, and a Sonnet worker costs 13× a Luna one. Workers do bounded research, so Luna's turn latency hurts less there than on the interactive path. Background bosses keep their workers on Luna as well, since `subAgent` is one route; that is accepted because sub-agent spend is small and the alternative is a second sub-agent route with no consumer that can tell them apart today.

**Alternatives rejected.** (a) **Keep Sonnet as the Auto fallback** — rejected by the user; a dear degrade leg for a cheap primary is the wrong shape. (b) **Keep Opus on Deep** — rejected for the same reason at a larger ratio; the Deep picker now buys effort, not vendor. (c) **No fallback at all on the chat tiers** — rejected: `withFallback` is the only cross-provider degrade for a 429 or a spend cap, and `gemini-3.8-flash` is already the degrade leg on boss, cheap, and the old deep route, so this adds no new model to the surface.

**Accepted risks.** (0) **An all-Luna boss plus workers has never been measured in Alfred.** The only all-OpenAI run was Sol boss + three Luna workers, which fanned out to 56 calls / 143s / `$0.617`. Watch fan-out count on delegating turns. (1) **Deep at `max` has no Alfred measurement.** The July bake-off ran Luna at `medium`. A flat `max` on the Responses API may multiply the 16-leg / 86s turn shape the first live Auto turn showed; Deep is opt-in, so the blast radius is bounded to turns the user escalates. (2) **The Anthropic prompt cache is gone from every chat leg.** Boss and sub-agent routes still use it. (3) **`gemini-3.8-flash` has still never run a real `generateText` turn with the full tool set**, and it is now the only degrade leg on both chat tiers. A 403 or a 400 on that leg is non-retryable and ends the turn. (4) **Luna is text/image/PDF only** on both tiers now, so no chat tier keeps Sonnet's wider modality set; ADR-0065 degrade-at-ingest governs attachments.
