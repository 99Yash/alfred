# ADR-0110 — A standing instruction hard-demotes its sender's surviving demand lane

**Decision.** The triage pipeline gains a fifth floor, `standing` (`packages/assistant/src/triage/floors/standing.ts`). When the category-lane read in `gatherObservations` matched the sender's active suppression — the same `standingInstruction` observation ADR-0106 renders into the prompt — a surviving `urgent` or `action_needed` is demoted to `fyi` through the shared floor convention: category `fyi`, todo and document ask cleared ("demote, never bury"), a reason clause naming the instruction's `factId` in the rationale, and the `+standingfloor` model tag. This amends ADR-0106's "prior, not floor" stance for the category lane only; the render-first placement, the `phrasing`-not-`directive` rule, and the derived-membership no-repair contract are untouched.

**Why prompt-only lost.** A month of `triage.classification` traces (September 26 → October 20, 2026) shows the Polylane and Smallcase upsert mail — exactly the "connect Supabase/Axiom/Trigger.dev" and "monitoring pauses" mail the user's instruction names — landing `urgent`/`action_needed` on `source = 'auto'` every time, with `standingInstructionCategoryFactId` matching in every trace. The escape hatch ("a genuinely urgent item judged from the body") was not a rare, model-judged exception; it was the standing route this sender's copy takes, re-decided by the same cheap model on the same urgency-dressed upsell wording each run. A judgment ADR-0106 calls deterministic-adjacent ("the user's own words") cannot outrank itself when the body dresses the same ask as an emergency every week.

**The floor shape reuses the demote convention.** The verdict never re-stamps the category by hand — `applyFloorVerdict` owns `fyi`, the todo clearing, and the note prefix (`standing_floor:`), so the audit cannot disagree with what landed. The floor fires only on the demand lanes; a `meeting` the user accepts, a `payment` due, and the already-passive lanes are out of scope by a lane table that is exhaustive over `TriageCategory`, so a new category fails the build rather than silently surviving.

**The bar stays above the user.** `matchesExposedSecret` — the override floor's own predicate over the same signal text — vetoes the demotion and reports `held_secret_lane` on a keep verdict. ADR-0106's protective line ("the security floor still outranks a user down-rank") is preserved deterministically rather than by prompt trust. A null instruction (no match) and a failed read both arrive as "keep": a blip must never over-suppress, and the trace's `standingInstructionCategoryReadFailed` already tells the two apart.

**Trace.** `standingFloorOutcome` (`demoted_demand_lane` / `held_secret_lane`, or null) mirrors the spam floor's `spamFloorOutcome`: the held value hangs off a `keep` verdict, so counting demotions is `= 'demoted_demand_lane'`, never `IS NOT NULL`. `standingDemotedCategory` is the boolean twin. The audit's demotion note carries the instruction `factId`, so a trace joins back to the `user_facts` row.

**Prompt wording moved with it.** `STANDING_INSTRUCTION_HANDLING_RULE` no longer tells the model a demand lane may survive — it states the enforcement, so the model stops being invited to spend a lane the fold removes. The rule stays inside the conditional render branch (ADR-0106's placement lesson): mail with no matched instruction sees a byte-identical prompt.

**Stated cost.** A genuinely one-off urgent message from a suppressed sender (for example, a real suspension notice from Polylane) now lands `fyi` with its rationale saying why, instead of `urgent`. That is the accepted meaning of a sender-wide suppression: the user asked for the whole sender to be deprioritized, the todo lane already suppresses it, and the countable `held_secret_lane` outcome keeps the override's escape visible where it actually fires. Reinstatement stays a chat instruction away — delete the fact, and the floor goes inert with no code change.
