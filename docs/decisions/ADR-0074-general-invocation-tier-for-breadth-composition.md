# ADR-0074 — General invocation tier for breadth, composition, and BYO-MCP: a raw read-passthrough now-ish, Code-Mode-style sandboxed code later (FRAMED — DEFERRED, not designed)

**Decision (framed, not designed).** Breadth — "the boss should be able to do anything the API can, including future user-supplied MCP servers" — is served by a **general tier** sitting beside the curated typed tier (ADR-0071), **not** by hand-modeling every endpoint. Two rungs, both deferred: **(a)** a **raw read-only passthrough** per integration (`<integration>.request(path, params)`), the lighter near-term escape hatch for the long tail; **(b)** a **Code-Mode-style sandboxed code tier** (the boss writes code against a typed binding of an MCP/OpenAPI surface, executed in an isolate — per Cloudflare's Code Mode) as the timeless substrate for many-tools, multi-step composition, and bring-your-own-MCP. Both rungs **inherit the result-honesty primitive** (ADR-0071 #6) as their correctness layer, since neither can pre-validate the long tail.

**Why.** The owner's instinct ("if it's in the API it should be there; ideally do anything; users will bring their own MCP servers") is correct for the **invocation/coverage/composition axis** — and Code Mode is the strongest known answer there (fixed token cost regardless of endpoint count, composition without per-call LLM round-trips, auto-binding arbitrary servers). But — confirmed from the Code Mode posts — it _"addresses composition and invocation… no parameter validation or schema enforcement beyond what the model infers."_ So Code Mode does **not** solve the bug that motivated this batch: GitHub's silent-zero on a bad qualifier is a **correctness-of-a-given-call** property, orthogonal to how the call is invoked; the model writing `q:"merged-by:@me"` _in sandboxed code_ still gets a confident zero. The two axes must not be conflated: this batch builds correctness (ADR-0070/0071/0072); the general tier is breadth, and it still needs the result-honesty primitive on top.

**Constraints to design against (when picked up).** Deployment is **Railway + Cloudflare R2**, runtime is the **Vercel AI SDK** — _not_ Cloudflare Workers, so Code Mode's free isolate (V8, no-FS, outbound-off, OAuth-downscoped) is not in hand. Hosting model-authored code that holds the user's Gmail/GitHub/Railway credentials is a **prompt-injection exfiltration surface**; an equivalent sandbox must be built or borrowed (isolated-vm / a Deno subprocess / a microVM, or spinning up CF Durable-Object/facet isolates from Railway) and whether the Vercel AI SDK can cleanly host a single `execute()` tool is open. The (b) passthrough also needs a cross-integration risk model (read-only scoping, cost attribution, auditability) — the same weigh-in deferred from the GitHub grill.

**Alternatives.** (a) **Hand-curate to ~100% coverage** — rejected: unmaintainable, never complete, and can't cover the prose-only DSL layer (ADR-0071's maintenance policy). (b) **Adopt Code Mode now** — rejected: a heavy, security-critical commitment that is its own grill, and it would not have prevented the motivating bug. (c) **Skip the general tier entirely** — rejected: forecloses BYO-MCP and the obscure-query long tail the owner explicitly wants.
