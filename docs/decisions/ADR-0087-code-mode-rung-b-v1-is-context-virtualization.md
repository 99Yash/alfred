# ADR-0087 — Code-Mode rung-(b) v1 is context virtualization, not composition/BYO-MCP: object handles + a network-less self-hosted isolate whose only capabilities are host functions (DESIGNED — grilled 2026-07-21; substrate amended 2026-08-19 to `@ai-sdk/code-mode` over QuickJS-in-WebAssembly, which reverses alternative (d); see docs/plans/code-mode-object-handles-v1.md)


**Decision.** Rung-(b) of ADR-0074 is scoped down to one job the curated tier and rung-(a) cannot do: **keep a large tool result out of the transcript and let the boss compute derived results over it in code.** (1) **Auto-park at the existing rung-(a) truncation bound** (>32 KiB / >50 items / >8 000-char string, reusing `packages/api/src/modules/tools/passthrough/bounds.ts`): a result that would truncate is instead written to object storage and the transcript receives only `{ handle, preview, schema, rowCount, provenance }`. (2) **Handles live in R2 (blob) + a Postgres metadata row, thread-scoped with a TTL** so a follow-up turn in the same thread can still `load(handle)`; GC on expiry. (3) The **sole interface** to a handle is `code.run(source)` — model-authored **JS/TS**, no query DSL and no non-code peek path. (4) Execution is a **self-hosted `isolated-vm` V8 isolate running inside a forked worker process**, reached over an **IPC bridge** from the main API process; **the isolate has zero network access**. (5) Its **only capabilities are host functions injected over the bridge** and executed in the trusted process — `load(handle)` (a **paged cursor** over the R2 blob, so the payload never has to fit in isolate memory), `broker.read(...)` (a **thin facade over the rung-(a) passthrough** — same read gate, transport, shaper, and honest envelope), and `broker.write(...)`. **Credentials never enter the isolate**; the main API process is the only credential holder, so a V8 sandbox escape lands in a disposable, cred-less, network-less worker rather than the process that holds every token. (6) **Writes are plan-then-apply**: a dry-run emits the write set for user approval, then apply executes it; the run is made replayable by **hashing code + inputs** (the approved plan is cached under that hash), and the plan-to-apply TOCTOU window is closed by a **drift-guard on the write targets only** — at apply, re-read exactly the entities the plan will mutate and abort if they changed since the plan was built. (7) Every `code.run` return **carries forced provenance** (which broker reads fed the result, and any read that errored or came back empty) so the boss cannot launder a structural confident-zero, inheriting ADR-0071 #6 and guarded by a behavioral eval in the style of `passthrough-honesty.eval.ts`; a return value over the park bound **re-parks recursively** as a new handle. (8) Ships **on-by-default for the single user** — coherent because data never leaves Alfred's own infrastructure — and graduates from "experiment" only when new code-run telemetry (runs / aborts / escape-attempts) plus the rung-(a) truncation thermometer justify widening.

**Amendment (2026-08-19) — the substrate is `@ai-sdk/code-mode` over QuickJS-in-WebAssembly, and it reverses alternative (d).** Decision points (1), (2), (3), (7), and (8) stand. Point (4) keeps its intent and changes its implementation. Alfred does not build an `isolated-vm` isolate in a forked worker process. It calls `experimental_runCodeMode` from `@ai-sdk/code-mode`, which wraps `run@2.0.0` (`vercel-labs`, Apache-2.0, **zero runtime dependencies**). The facts below come from a probe of the published `@ai-sdk/code-mode@1.0.25` and `run@2.0.0` tarballs. `run` embeds a **1,027,523-byte QuickJS WebAssembly module** (built by `quickjs-emscripten` 0.32.0, magic bytes `00 61 73 6d`) and starts it in a `node:worker_threads` `Worker` from a `data:text/javascript` URL with `execArgv: []`. It is a library, not a hosted service. A probe of the published tarball found no `node:vm`, no `isolated-vm`, and no HTTP, socket, or DNS client in the host code. The rejection of Freestyle.sh in alternative (b) therefore does not extend to this package: no request leaves Alfred's own process, so data custody is unchanged.

**Point (5) is the package's native model, so two open verification items close.** `run` takes `hostFunctions` groups, exposes each group as one global inside the sandbox, and permits **async** host functions. `load(handle)` as a paged cursor and `broker.read(...)` as a facade over the rung-(a) passthrough are therefore ordinary async functions in the trusted process, and the `isolated-vm` `applySyncPromise` question is moot. Guest code starts with no `fetch`, no timers, no `crypto`, no environment variables, no modules, no filesystem, and no dynamic evaluation; built-in prototypes are frozen and only own properties of a host-function group are reachable. "Zero network" is now **structural rather than configured**, so the plan's operating-system egress-denial proof is not required. Resource caps are documented and overridable per run: 30 s timeout, 64 MiB QuickJS memory, 2 MiB stack, 256 KiB source, 1 MiB result, 64 KiB console output, 1 MiB host-function input, 4 MiB host-function output, 256 bridge requests, and 32 concurrent bridge requests. The worker pool cap is process-wide and set through `experimental_setMaxWorkers`. Every run receives a fresh QuickJS context, and a worker that cannot reach a verified clean state after an abort, a timeout, or a protocol failure is retired.

**Alternative (d) is reversed: the sandbox now runs in a worker thread inside the credential-holding process.** The original rejection assumed `isolated-vm`, where guest JavaScript executes directly in a V8 isolate, so **one** V8 bug reaches the tokens. Here guest JavaScript never reaches V8. QuickJS interprets it inside WebAssembly linear memory, and V8 confines that WebAssembly module. An escape needs a QuickJS bug **and** a WebAssembly sandbox escape, so the guest sits behind two boundaries instead of one, and the outer boundary is the one V8 hardens hardest. The worker thread still contains crashes and enforces the caps above. **Accepted residual risk:** the process continues to hold every token, and a worker thread shares that process. A `child_process.fork()` around `runCodeMode` remains available as cheap hardening, and telemetry from the owner experiment decides whether to add it. Alternative (e) (Firecracker/gVisor) stays the graduation path.

**Point (6) gains a stronger replay mechanism than "hash code + inputs", and keeps its drift guard.** `run` supports `interrupt(payload)` inside a host function, which suspends the run and returns a **signed continuation**; a later call resumes it with resolutions. `@ai-sdk/code-mode` exposes this as `approval: { mode: 'interrupt' }` plus `experimental_continueCodeModeApproval`. A continuation carries a replay ledger: on resume the runtime replays the program, reads completed and rejected host functions from the ledger instead of calling them again, and verifies the transformed source, the host-function-name manifest, and the complete serialized argument list of every call. It rejects divergence **before** a mismatched host function runs, and it keeps guest `Date`, `Date.now()`, and `Math.random()` deterministic across the replay. `continuationContext` binds the token to Alfred's user, thread, and policy version. This supersedes the hand-rolled hash. Four obligations remain Alfred's: (i) the **drift guard on write targets** still owns the plan-to-apply TOCTOU window, because the ledger detects code divergence and not entity change; (ii) the resume endpoint must authorize the actor who submits each resolution, because a valid continuation proves integrity and scope but grants no approval; (iii) an interrupted host function **is reinvoked** on resume, so `broker.write` must call `interrupt()` before any non-idempotent work and use `resume.interruptionId` as its idempotency key; (iv) a signed continuation is a replayable bearer token whose payload is base64-encoded but **not encrypted**, so writes use `createStoredContinuationCodec()` (at-most-once, storage-claimed) rather than the signed codec, and every process that creates or resumes one needs the same 32-byte secret.

**What this amendment does not change.** The handle substrate is still Alfred's to build: auto-park at the rung-(a) bound, the R2 blob, the Postgres metadata row, thread scope, TTL, garbage collection, and the honest fallback when storage fails. Forced provenance (point 7) is still Alfred's, and it stays trustworthy for the same reason as before: Alfred owns the host functions, so the host-side load ledger is authoritative and guest code cannot forge it. Recursive re-park of an over-bound return is still Alfred's. Most important, **the evidence gate is unmoved**: the rung-(a) truncation thermometer has still not fired. A cheaper sandbox lowers the cost of the experiment; it does not create the need. **Adoption costs, named:** `@ai-sdk/code-mode` declares an **exact** `ai` peer and the two move in lockstep, one pair per release (`1.0.22`↔`7.0.65`, `1.0.23`↔`7.0.66`, `1.0.24`↔`7.0.67`, `1.0.25`↔`7.0.68`). Choosing a code-mode version therefore chooses the `ai` catalog pin, and the AI SDK publishes several releases a day, so the newest pair is normally younger than pnpm's 24-hour release-age floor. The floor wins: the catalog moved from `7.0.19` to **`7.0.66`**, which is the newest pin that cleared the floor on the bump date and is the exact peer of `@ai-sdk/code-mode@1.0.23`. Do not chase the newest pair, and do not relax the floor to reach it; `minimumReleaseAgeExclude` is honored when pnpm resolves but **not** when it verifies an existing lockfile, so a too-new transitive package (here `@ai-sdk/gateway`) blocks every later `pnpm install` even with an exclude entry present. Every export carries the `experimental_` prefix, so the API may change. `github.com/vercel-labs/run` is not public, but the published sourcemaps carry full `sourcesContent`, so the code is reviewable; pin it exactly and re-review on each bump. Two items in the plan's "superseded during the grill" list gain company: the **IPC bridge** and the **forked worker process** are superseded too, along with the hash-based replay. Path correction for readers of the original text: the rung-(a) passthrough now lives at `packages/assistant/src/tool-runtime/internal/tools/passthrough/`, not `packages/api/src/modules/tools/passthrough/` (ADR-0089 extraction).

**Why.** The grill (2026-07-21) established, against receipts, that **two of ADR-0074's three stated drivers for this rung are already dead**: the token-cost of many tool definitions was solved by the lazy tool surface (#405/#411/#412/#414 — kernel is 8 tools, ratchet-guarded by `schema-budget.test.ts`), and multi-step composition latency is **unmeasured and speculative** (the one time chat latency was profiled, the multi-minute gaps were a DB-orchestration bug, and the real fan-out case was fixed by *curation* — `github.search` — not a code tier). BYO-MCP is owner-instinct with **zero user demand at n=1**. The **only live justification** is context virtualization via object handles — the L0 layer already sketched in `docs/plans/context-working-set-considered.md` and gated by the rung-(a) truncation thermometer, **which has not yet fired**. So this ADR is deliberately a **security-critical experiment built ahead of proven need**, undertaken to learn; that trade is named, not hidden. The containment model is the crux: because the isolate holds no credentials and has no network, there is nothing for prompt-injected model-authored code to exfiltrate and nowhere to send it — the two failure modes ADR-0074 flagged (a cred-holding sandbox; an open egress path *from the isolate*) are designed out rather than mitigated. **Accepted residual risk (named, not covered):** the no-network/no-cred isolate closes exfil *by the injected code*, but not the loop that code feeds — a `code.run` return value re-enters the transcript, and the boss orchestrator still has egress via its legitimate tools (`gmail.send`, etc.). So injection → `broker.read` private data → boss-steered send through a real tool remains open; it is the general agent-exfil problem, unchanged by this rung, and is *not* what the isolate boundary addresses. The forced-provenance return contract (#7) targets a different failure mode — laundering a structural confident-zero — not this one. The forked-worker boundary is cheap insurance for the one process that must hold every token.

**Alternatives.** (a) **Bounded query DSL / a non-code `read_object(handle, jsonpath, page)` peek path** — considered and rejected by the owner (twice), who wants code as the interface; noted here because it would have delivered context virtualization with *no* isolate and *no* security surface, and remains the honest off-ramp if the isolate cost outruns the (still-unproven) need. (b) **Freestyle.sh (SaaS V8 Serverless Runs)** — evaluated in depth: it satisfies the egress-allowlist-to-one-host and sub-100ms-run constraints out of the box, but was **rejected on data custody** — it runs in a third-party cloud with no VPC/self-host, which would force the credential-broker to be *publicly* exposed and would route the user's private Gmail/GitHub/Railway reads through a third party in a V8 (not microVM) boundary, with SOC 2 / residency / egress-enforcement-layer all undocumented. (c) **RPC-to-broker over the network + a public broker hardened with mTLS + per-run token** — this was the mid-grill design until (b) was rejected; **superseded** by host-injected capabilities, which delete the network path, the public broker, and the egress allowlist entirely. (d) **Run the isolate in the main API process** — rejected: a V8 escape would be immediately inside the credential-holding process; the forked worker restores a boundary for negligible cost. (e) **Firecracker/gVisor microVM per run** — the strongest isolation for hostile code and the "correct" answer at scale, but real operational weight for a single-user experiment; deferred as the hardening path if this graduates. (f) **Record-and-replay the full broker trace** (instead of hash code+inputs) — rejected as heavier than the experiment warrants; the drift-guard on write targets covers the dangerous half of the TOCTOU window that plain hashing leaves open.
