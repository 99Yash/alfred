# ADR-0087 — Code-Mode rung-(b) v1 is context virtualization, not composition/BYO-MCP: object handles + a network-less self-hosted isolate whose only capabilities are host functions (DESIGNED — grilled 2026-07-21, see docs/plans/code-mode-object-handles-v1.md)


**Decision.** Rung-(b) of ADR-0074 is scoped down to one job the curated tier and rung-(a) cannot do: **keep a large tool result out of the transcript and let the boss compute derived results over it in code.** (1) **Auto-park at the existing rung-(a) truncation bound** (>32 KiB / >50 items / >8 000-char string, reusing `packages/api/src/modules/tools/passthrough/bounds.ts`): a result that would truncate is instead written to object storage and the transcript receives only `{ handle, preview, schema, rowCount, provenance }`. (2) **Handles live in R2 (blob) + a Postgres metadata row, thread-scoped with a TTL** so a follow-up turn in the same thread can still `load(handle)`; GC on expiry. (3) The **sole interface** to a handle is `code.run(source)` — model-authored **JS/TS**, no query DSL and no non-code peek path. (4) Execution is a **self-hosted `isolated-vm` V8 isolate running inside a forked worker process**, reached over an **IPC bridge** from the main API process; **the isolate has zero network access**. (5) Its **only capabilities are host functions injected over the bridge** and executed in the trusted process — `load(handle)` (a **paged cursor** over the R2 blob, so the payload never has to fit in isolate memory), `broker.read(...)` (a **thin facade over the rung-(a) passthrough** — same read gate, transport, shaper, and honest envelope), and `broker.write(...)`. **Credentials never enter the isolate**; the main API process is the only credential holder, so a V8 sandbox escape lands in a disposable, cred-less, network-less worker rather than the process that holds every token. (6) **Writes are plan-then-apply**: a dry-run emits the write set for user approval, then apply executes it; the run is made replayable by **hashing code + inputs** (the approved plan is cached under that hash), and the plan-to-apply TOCTOU window is closed by a **drift-guard on the write targets only** — at apply, re-read exactly the entities the plan will mutate and abort if they changed since the plan was built. (7) Every `code.run` return **carries forced provenance** (which broker reads fed the result, and any read that errored or came back empty) so the boss cannot launder a structural confident-zero, inheriting ADR-0071 #6 and guarded by a behavioral eval in the style of `passthrough-honesty.eval.ts`; a return value over the park bound **re-parks recursively** as a new handle. (8) Ships **on-by-default for the single user** — coherent because data never leaves Alfred's own infrastructure — and graduates from "experiment" only when new code-run telemetry (runs / aborts / escape-attempts) plus the rung-(a) truncation thermometer justify widening.

**Why.** The grill (2026-07-21) established, against receipts, that **two of ADR-0074's three stated drivers for this rung are already dead**: the token-cost of many tool definitions was solved by the lazy tool surface (#405/#411/#412/#414 — kernel is 8 tools, ratchet-guarded by `schema-budget.test.ts`), and multi-step composition latency is **unmeasured and speculative** (the one time chat latency was profiled, the multi-minute gaps were a DB-orchestration bug, and the real fan-out case was fixed by *curation* — `github.search` — not a code tier). BYO-MCP is owner-instinct with **zero user demand at n=1**. The **only live justification** is context virtualization via object handles — the L0 layer already sketched in `docs/plans/context-working-set-considered.md` and gated by the rung-(a) truncation thermometer, **which has not yet fired**. So this ADR is deliberately a **security-critical experiment built ahead of proven need**, undertaken to learn; that trade is named, not hidden. The containment model is the crux: because the isolate holds no credentials and has no network, there is nothing for prompt-injected model-authored code to exfiltrate and nowhere to send it — the two failure modes ADR-0074 flagged (a cred-holding sandbox; an open egress path *from the isolate*) are designed out rather than mitigated. **Accepted residual risk (named, not covered):** the no-network/no-cred isolate closes exfil *by the injected code*, but not the loop that code feeds — a `code.run` return value re-enters the transcript, and the boss orchestrator still has egress via its legitimate tools (`gmail.send`, etc.). So injection → `broker.read` private data → boss-steered send through a real tool remains open; it is the general agent-exfil problem, unchanged by this rung, and is *not* what the isolate boundary addresses. The forced-provenance return contract (#7) targets a different failure mode — laundering a structural confident-zero — not this one. The forked-worker boundary is cheap insurance for the one process that must hold every token.

**Alternatives.** (a) **Bounded query DSL / a non-code `read_object(handle, jsonpath, page)` peek path** — considered and rejected by the owner (twice), who wants code as the interface; noted here because it would have delivered context virtualization with *no* isolate and *no* security surface, and remains the honest off-ramp if the isolate cost outruns the (still-unproven) need. (b) **Freestyle.sh (SaaS V8 Serverless Runs)** — evaluated in depth: it satisfies the egress-allowlist-to-one-host and sub-100ms-run constraints out of the box, but was **rejected on data custody** — it runs in a third-party cloud with no VPC/self-host, which would force the credential-broker to be *publicly* exposed and would route the user's private Gmail/GitHub/Railway reads through a third party in a V8 (not microVM) boundary, with SOC 2 / residency / egress-enforcement-layer all undocumented. (c) **RPC-to-broker over the network + a public broker hardened with mTLS + per-run token** — this was the mid-grill design until (b) was rejected; **superseded** by host-injected capabilities, which delete the network path, the public broker, and the egress allowlist entirely. (d) **Run the isolate in the main API process** — rejected: a V8 escape would be immediately inside the credential-holding process; the forked worker restores a boundary for negligible cost. (e) **Firecracker/gVisor microVM per run** — the strongest isolation for hostile code and the "correct" answer at scale, but real operational weight for a single-user experiment; deferred as the hardening path if this graduates. (f) **Record-and-replay the full broker trace** (instead of hash code+inputs) — rejected as heavier than the experiment warrants; the drift-guard on write targets covers the dangerous half of the TOCTOU window that plain hashing leaves open.
