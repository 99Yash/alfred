# ADR-0067 — Multi-source user-model substrate: an event-sourced observation log as the system of record, with entities/identities/relations/significance/facts as replayable projections (extends ADR-0012/0056/0057/0062; amends ADR-0057's direct-upsert capture; re-scopes ADR-0066; Tier of #218)


**Decision.** Replace the single-source, aggregate-counter entity graph with an **append-only, multi-source observation log as the system of record**. Every integration (Gmail, Google Calendar, GitHub, ClickUp, Notion, …) reduces its raw events into normalized `observations`; **entities, cross-source identities, relations, the social graph, significance, and facts are all deterministic, replayable projections** over that log. Email becomes *one source among many* — the highest-signal sources Alfred has (who you **meet with**, who you **ship code with**) finally feed the model. This is the foundation of the #218 user-model spine; ADR-0066's triage rewrite becomes a *consumer* of it.

**Why.** A prod read (work account, 2026-06-23) found the graph is structurally broken, not buggy: entities mined **only** from Gmail headers (calendar/GitHub people deferred in code); GitHub repos and `dev.N@` test accounts stored as `kind: person`; a distribution alias (`'Anthropic' via Engineering`, `engineering@oliv.ai`) is the **top-scored "person" at 0.72**, outranking every human; the entire standup list scores an identical flat `0.368` (reciprocity pinned, `coRecipient` inflation); no cross-source identity (`sanyam-oliv` ≠ `sanyam.p@oliv.ai`); `user_facts` is 92% document ephemera auto-confirmed at 0.95 (Zoom passcodes, alarm names); `integration_object_relations` empty for all users (#212 never wired the object↔entity edges — no resolver existed). These are one disease — the **wrong substrate** — and patching the email pipeline cannot fix multi-source, identity, provenance, or recompute. The event-sourced log makes the model **recomputable** (change a weight/cutoff/classifier/ontology → replay the fold) and **uniform across sources** (one reducer-per-provider registry, the proven ADR-0062 pattern).

**The shape.** `observations` (append-only, **event-grain** — one row per relationship-bearing email/meeting occurrence/PR-event evidence with the full participant set + `recipientCount` + `list_id` in `participants`; every reducer emits `family_key` and `evidence_hash`, deduped by the unique `(user_id, family_key, evidence_hash)` index (no stored `dedup_key` concat — a denormalized `family_key:evidence_hash` would be a second source of truth a reducer could miscompute), so identical relationship evidence dedupes and changed attendees/start/reviewers/assignees append a superseding observation; retained indefinitely in v1 because storage is the price of replay/audit/future reducer fixes) → stable identity layer → versioned read models. Stable: `entity_nodes` (content-addressed stable node ID + supersession/forwarding; no `projection_version`) and `entity_identities` (typed identity keys, **active-row unique `(user_id,kind,value) WHERE valid_until IS NULL`** — partial, so a freed/reused mutable handle closes its old row and re-anchors on a new entity without a false bridge; the LIVE set is the dedup index + observation join target, replacing the untyped `aliases` blob). Versioned: `entity_profiles` (display/kind/significance components over stable `entity_id`), `entity_edges` (typed: `works_at`, `member_of`, `reports_to`, `frequent_collaborator`, `in_org`), and `entity_co_occurrence` (full social graph as a **weighted pair projection** — fan-out cutoff zeroes blast cliques, promotion threshold lifts only strong pairs to traversable edges). `user_facts` subject-binding is P4-deferred; ephemera stays in `memory_chunks`/RAG. Any projection row that becomes Replicache-visible exposes a stable logical sync key plus content version; active-version flips must patch per-key deltas, not delete-all + re-add-all.

**Key sub-decisions** (full rationale + alternatives in the plan). **Identity merge = deterministic-first + reversible proposals over stable IDs** — auto-merge only on a hard bridge (shared email; GitHub **commit-author email** from `push` payloads; a confirmed `github_username` fact; verified Google Workspace Directory profile/email when [`directory.readonly`](https://developers.google.com/people/api/rest/v1/people/listDirectoryPeople) + domain sharing are available), name matches *proposed*/gated/reversible (propose-dispose, ADR-0062), unmapped logins live as provisional stable entities merged later via supersession; coverage is partial by design (masked `noreply` commit emails don't bridge — fall back to the fact). Entity IDs are the foreign-key contract: P2/P4/P5 cutovers move `integration_object_relations.entity_id`, `user_facts.subject.id`, and future todo/briefing/meeting-prep refs to stable IDs; the stable node id is content-addressed from a single normalized hard identity via an **HMAC-keyed** hash — `ent_${base32(hmacSha256(secret, {v:1, userId, identityKind, normalizedValue}))}` (keyed, not raw SHA, because ids are guessable and surface in client sync/logs; `computeStableEntityId` in `@alfred/db`, secret from `serverEnv`), never seeded from display name/kind/significance/random/version. (Earlier "first normalized hard identity" wording was rejected as too arrival-order-sensitive for a P0 FK contract.) The **merge survivor is the node seeded by the highest anchor-rank identity** in the merged hard-bridge component (`identityAnchorRank`, lower wins: user-pin/correction → verified Workspace directory → email → provider immutable account id (`github_user_id`/`slack_id`/`notion_user_id`) + org domain → provider mutable handle (`github_login`) → provisional), tie-broken by earliest **`entity_nodes.first_seen_at`** (the node's earliest observation timestamp, supplied by the writer at mint time, never a wall clock — so the order is replay-deterministic; identity rows carry only `valid_from`/`valid_until`, not a `first_seen_at`) → value lexicographic → id lexicographic — not newest/oldest row, not whichever source triggered the merge. Merges write forwarding pointers on losers, never rewrite external FKs synchronously, and all reads resolve through that chain (`resolveActiveEntityId`); loser ids remain permanent forwarding aliases. **Event-grain with evidence hashing** so a 50-recipient blast is *one* down-weighted observation, not 50 `coRecipient` touches, and append-only still supports material edits: a Calendar occurrence or GitHub PR family has one active relationship-evidence member per `family_key`, identical `evidence_hash` no-ops, changed attendees/start/reviewers/assignees append a row with `supersedes_observation_id`; Calendar occurrence identity uses fields such as `recurringEventId` + `originalStartTime` from the [Calendar Events API](https://developers.google.com/workspace/calendar/api/v3/reference/events). **Full social graph** kept viable by the weighted-pair projection + fan-out cutoff + promotion (full graph, bounded size, near-linear writes, cheap traversal, recomputable). **Significance stays deterministic** (the event-sourced choice forbids replaying an LLM over all history per weight change), but the projection materializes only time-invariant components (`volume`, `reciprocity`, `sameOrg`, raw/source-weighted interaction weights, raw co-occurrence weight, provenance — `lastSeenAt` is a first-class sibling column on `entity_profiles`, NOT a significance component, because a wall-clock value inside the checksummed set would break replay determinism); final score = `baseScore(components) * recencyMultiplier(asOf,lastSeenAt)` at read time, so replay checksums are stable without daily decay recomputes. **Non-humans are typed nodes, not suppressed** (queryable, recomputable, no signal lost), never person-scored; because a better classifier may change `kind`, kind lives in versioned `entity_profiles`. **`integration_object_relations` is a P2 resolver cutover** — GitHub webhooks will emit both social observations and object↔stable-entity edges; P0 keeps the existing legacy FK until the resolver lands. **User actions are observations too** — chat-captured standing instructions, confirmations/rejections, manual edits, and corrections are `user`/`alfred_chat` observations; the fold resolves conflicts by source rank first (`user` > `alfred_chat` > first-party integrations > enrichment/RAG), then recency within rank. Existing non-proposed `user_facts` rows, not only `standing_instruction`, migrate into `source='user'` observations; status/confidence must be replay-derived from confirmation/edit/rejection observations so confirmed facts do not downgrade to proposed. **Reducers separate raw events from relationship evidence** — Calendar updates/retries do not count as extra meetings; GitHub webhook edits/retries do not inflate significance. **D10 vs D13 are different lifecycle events** — D10 is the one-time substrate migration from the old aggregate graph to the new append-only/projection graph, including legacy-column drops; D13 is steady-state projection re-versioning for weight/ontology/reducer changes, with no schema drop. **Projection versions are checkpointed and consumed through active views** — each projection run records version, source high-watermark, counts/checksums, active cutover pointer, and Replicache-visible sync state `(sync_slug, stable_key, content_hash, row_version)`; only recomputed outputs are version-tagged (`entity_profiles`, `entity_edges`, `entity_co_occurrence`, P4 `user_facts`), while stable `entity_nodes`/`entity_identities` are not. Consumers read `active_entity_profiles`/`active_entity_edges`/`active_entity_co_occurrence`/`active_user_facts` views rather than hand-writing `WHERE projection_version = active`; any active view wired to Replicache exposes `id = stable_key` and a synthetic rowVersion/content version that changes only when serialized content changes. Checksums use deterministic row order and rounded floats over time-invariant components only; any top-N comparison that uses final scores pins a validation `asOf`. **Migration = shadow-build + validated cutover** — new tables coexist, replay all sources, validate coverage against the old graph (counts, expected identities/source families present) while treating legacy top-N ordering as polluted and expected to diverge; correctness comes from deterministic replay checks, spot-checks, and a projection-sync cutover test proving unchanged stable keys do not produce a Replicache `put`/`del` storm; then flag-flip and drop legacy; idempotent by the unique `(user_id, family_key, evidence_hash)`, dry-run local, prod replay via `railway ssh`.

**What stays invariant.** Postgres + recursive-CTE traversal — **ADR-0058 honored** ("build the intelligence, don't buy the store"; the log + projections are not a graph DB). This follows the standard event-store/materialized-projection pattern ([Microsoft](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)) while keeping Alfred's source of truth local; Graphiti/Zep's temporal graph validates the model direction but still wants a graph backend ([Graphiti](https://github.com/getzep/graphiti)), so it remains a pattern source, not a store. Gmail list detection relies on the [RFC 2919 `List-Id`](https://datatracker.ietf.org/doc/rfc2919/) header; Workspace Directory is conditional on People API domain-directory access ([People API](https://developers.google.com/people)). Third-party enrichment remains optional/proposed-only; the Proxycurl shutdown is the cautionary LinkedIn-dependency example ([Proxycurl postmortem](https://nubela.co/blog/goodbye-proxycurl/)). Single-user FK CASCADE. The reducer-per-provider registry pattern (ADR-0062). Significance as "one computed signal, four consumers" (ADR-0059). Tunable knobs as text columns + `@alfred/contracts` boundary validation, never pg enums (migration ergonomics).

**Alternatives.** (a) **Keep aggregate counters, add source tallies** — rejected: lossy, unrecomputable, can't model a calendar/GitHub relation, no provenance; patches the symptom. (b) **Hybrid counters + thin event log** — rejected: two write paths that drift (worst-of-both). (c) **Literal per-event person↔person edges** — rejected: clique explosion (a 50-person thread = 1,225 noise edges), super-linear writes, dense traversal. (d) **Suppress non-humans at ingest** — rejected: loses signal a replay can't recover; the filter logic still has to live somewhere. (e) **Eager LLM-assisted cross-kind merge** — rejected: a wrong merge corrupts a node and is hard to detect; fragmented-but-correct beats fused-but-wrong. (f) **In-place rebuild / forward-only backfill** — rejected: empty-graph window on the live account / wastes the history in `documents`+`webhook_events`. (g) **Buy a graph DB** — rejected (ADR-0058 re-affirmed). (h) **Build ADR-0066's cleanup independently on the email-only graph** — rejected: two systems on the same tables + a guaranteed second migration; 0066 consumes this foundation instead.

**Sequencing.** ADR + plan first (this), then incremental, Gmail-first, each phase shadow-built + validated: **P0 ✅ built 2026-06-23** (branch `feat/user-model-substrate-p0`, migrations `0050`–`0066`, additive) — schema + `@alfred/contracts/user-model.ts` registries + projection run/cursor tracking + Replicache projection-sync state; stable layer `entity_nodes`/`entity_identities` (content-addressed ids, unversioned) vs versioned `entity_profiles`/`entity_edges`/`entity_co_occurrence`, with the locked constants (`FAN_OUT_CUTOFF=12`, `PROMOTION_THRESHOLD=2.0`, `PROMOTION_MIN_OBSERVATIONS=3`, `PROMOTION_MIN_FAMILIES=2`, `SOURCE_WEIGHTS`). P0 also locks unambiguous projection cutover identity (`projection_runs` unique by user/name/version, `active_run_id`, run-scoped cursors), typed observation/projection jsonb envelopes, numeric DB checks, **composite tenant/family-integrity FKs on every denormalized `user_id` reference** (`0053` — a row can't point at another user's or another family's record; same pattern as `active_projection_versions`), and the optional `ENTITY_ID_NAMESPACE` env contract for the future HMAC id writer. **`0054` extends the composite pattern to the self-referential rails:** supersession/forwarding pointers are composite self-FKs (`observations` binds `(user_id, family_key, supersedes_observation_id)` — a supersession can't cross users or families; `entity_nodes`/`entity_identities` bind `(user_id, …)`); the observation chain is DB-provably fork-free via a partial-unique `(user_id, family_key, supersedes_observation_id)` (≤1 successor per predecessor; reducer owns CAS-retry + cycle detection); the redundant `observations.dedup_key` concat was dropped for a unique `(user_id, family_key, evidence_hash)`; and the versioned output tables carry `projection_run_id` with a composite FK to `projection_runs` so rows provably belong to one concrete run (dead-run orphans identifiable + deletable). **`0055` tightens that run FK to span `projection_version`** (`(user_id, projection_version, projection_run_id) → projection_runs(user_id, projection_version, id)`): a row's own `projection_version` is now DB-bound to its run's, closing the gap where a row tagged version-1 could point at a version-2 run and leak into the wrong active view. **`0056` closes the last review round:** the run FK is widened again to span `projection_name` (the versioned output tables now carry `projection_name`, bound in the unique slot + the 4-column run FK that reuses `projection_runs_active_fk_idx`) — `projection_runs` is generic (P4's `user_facts` projection reuses it), so name-binding stops a foreign-projection run from occupying the `(user, version, entity)` slot or being named by the FK; `entity_edges` gains `CHECK (from_entity_id <> to_entity_id)` (no self-relation a traversal would loop on; `entity_co_occurrence` already had it via `a < b`); three non-person identity kinds (`github_repository_id`, `github_repository_full_name`, `integration_object_key`) let `repository`/`project` nodes anchor a NOT NULL `canonical_identity` without abusing `github_login`/`domain`; and both `computeStableEntityId` and the `ENTITY_ID_NAMESPACE` env validator reject a secret with surrounding whitespace (the helper validated `.trim()` but HMAC'd the raw value — a stray space would silently remint every id). **`0057`–`0059` close the subsequent review rounds:** `0057` made the `entity_identities` unique an active-row partial (`WHERE valid_until IS NULL`, so a freed/reused mutable handle re-anchors without a false bridge), added the `entity_nodes.id` shape `CHECK ('^ent_[a-z2-7]{26}$')`, and added positive-version `CHECK (… >= 1)` across the version columns, while the contract boundary (`identityRefSchema.value`) began rejecting empty/surrounding whitespace to match the mint chokepoint. `0058` (contracts-mostly) dropped `lastSeenAt` from `significanceComponentsSchema` (a wall-clock value would break the D6/D13 checksum), added `isUserFactKey` (= `FACT_ONTOLOGY` ∪ `standing_instruction`) as the `user_facts.key` gate, and added `projection_name` to the versioned secondary indexes. `0059` registered a `google_directory` observation source (its `google_directory_id` identity + verified-directory anchor tier already existed, so a Directory row attributes to a real source instead of masquerading as `google_calendar`; profile/org-membership kinds land with the P3 reducer), switched `recipientCount` validation to count DISTINCT recipient identities rather than rows (a person in To+Cc, or a reviewer who is also an assignee, is one recipient — counting rows would force a correct reducer to inflate the count), added the `makeEntityNodeInsert` write helper so a node's content-addressed `id` and its stored `canonical_identity` cannot disagree (the DB id-shape CHECK can't recompute the HMAC — the invariant has to live at the write API), and dropped four redundant indexes (one exact duplicate + three left-prefixes of existing unique indexes — pure write tax on an append/replay-heavy substrate). **`0060`–`0061` close the latest rounds:** `0060` added an `observations_single_root_idx` partial-unique `(user_id, family_key) WHERE supersedes IS NULL` (the no-fork index's mirror — it serialized successors but said nothing about the head, so two distinct-evidence roots could fork a family at the head) plus non-empty `CHECK`s on `family_key`/`evidence_hash`; `0061` added an `entity_identities_value_nonempty` `CHECK (length(value) > 0 AND value = btrim(value))` — `value` is the live dedup key, so an empty/whitespace value is a merge magnet — and at the contract+mint chokepoints introduced the single `canonicalizeIdentityValue(kind, value)` canonicalizer (lowercase email/domain/github handle, leave opaque/numeric ids as-is): `identityRefSchema` now refuses a non-canonical value and `computeStableEntityId` refuses to mint from one, so `Person@x.com`/`person@x.com` can no longer mint two stable ids for one identity, while `makeEntityNodeInsert` runtime-PARSES the identity (a coerced bad kind can't mint a node) and now REQUIRES the observation-time `first_seen_at` (the merge tie-break, never a wall clock). **`0062`–`0063` close the latest rounds:** `0062` split a `CONTRIBUTOR_ROLES {committer}` bucket out of `RECIPIENT_ROLES` (a merge/squash bot `committer` or a 30-committer PR no longer inflates `recipientCount`/`FAN_OUT_CUTOFF`), added non-empty CHECKs on the projection identity keys (`projection_name`/`sync_slug`/`stable_key`/`content_hash`), and added run-lifecycle CHECKs (`status` enum + `status`/`completed_at` consistency); `0063` DROPPED the `entity_nodes.first_seen_at` `defaultNow()` (the replay-determinism-critical merge tie-break is now NOT NULL with no default — a writer that bypasses `makeEntityNodeInsert` and forgets it fails LOUD instead of recording wall-clock time) and added kind-specific identity-value FORMAT validation (`identityValueMatchesKind` — email/domain/github login+numeric ids/`owner/repo`/`integration_object_key` `provider:kind:id`; opaque ids stay at the non-empty+canonical floor) at BOTH the `identityRefSchema` boundary and the `computeStableEntityId` mint chokepoint, so a canonical-but-malformed value can't become a permanent `ent_*` anchor; the observation write-boundary parser is now recorded as a HARD P1 gate (no raw `.insert(observations)` before an `insertObservation`-style parser validates source→kind, participants, identity formats, lifecycle fields). **`0064`–`0066` close the determinism + counter hardening:** `0065` restored the `family_key`/`evidence_hash` whitespace CHECKs to the regex form (`0064` had briefly used `btrim()`, which only strips spaces) with `octet_length` byte caps, **dropped the `valid_from` `defaultNow()` on `entity_edges`/`entity_identities`** (same posture as `entity_nodes.first_seen_at` — semantic effective time must be supplied or the row fails LOUD, never a replay-time wall clock), added `valid_window` CHECKs on both, and added `projection_runs_completed_checksum_present` (a `completed` run MUST carry the non-empty checksum the activation guard compares); `0066` added the versioned-table `_run_idx` indexes (delete-by-run + run-scoped reads) and two `entity_co_occurrence` counter CHECKs (`family_count <= count`, `weight = 0 OR count > 0`). The 0053–0066 rails are pinned as a committed DB-backed regression test (`packages/api/test/contracts/user-model-rails.test.ts`, opt-in on `DATABASE_URL`); the full user-model suite is 52 tests, 0 failed, 0 skipped, with `drizzle-kit check` clean. New tables are named `entity_nodes`/`entity_edges` (not `entities`/`entity_relations`) to coexist with the legacy memory-module graph through the shadow phase; `user_facts` subject-binding + active-version views deferred to P4/P1 respectively · **P1** Gmail end-to-end + validate vs today, including the `engineering@oliv.ai` group/unscored fix · **P2** GitHub (commit-email bridges + wire stable-ID object_relations) · **P3** Calendar + conditional Google Workspace Directory (new ingestion, highest first-party people signals; verify `https://www.googleapis.com/auth/directory.readonly` is grantable and the `oliv.ai` admin-side profile/contact sharing toggle is enabled before adding it to `GOOGLE_FEATURE_SCOPES`) · **P4** fact ontology (subject-binding + purge; migrate all non-proposed user-authoritative facts into user observations; replay-derived status/confidence) · **P5** consumer cutover (triage/briefing/meeting-prep + re-scoped 0066) + Replicache delta validation + drop legacy.

**Implementation correction (2026-06-24).** The rollout is explicitly **source-by-source**, not a single bulk replay: P1 Gmail shadows `documents` first, P2 GitHub shadows `webhook_events` only after the stable-ID `integration_object_relations` cutover exists, and P3 Calendar/Directory lands after occurrence-grain hashing plus OAuth/admin verification. `ensureEntityNode` now preserves `entity_nodes.first_seen_at` with `LEAST(existing, excluded)` so replay order cannot move the merge tie-break later. P4 `user_facts` is a Replicache-visible projection cutover, not a plain table rewrite: define stable logical fact keys, backfill `projection_sync_state`, expose `active_user_facts` with synthetic row versions, and validate unchanged facts do not emit delete-all/re-add-all patches before retiring the legacy fact writer.
