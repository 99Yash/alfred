Completed down-pass review of PR #716 (Replicache poke bus port inversion). The structural claim holds: no `assistant → api` edge, zero SCCs, interface properly isolated. However, discovered a breaking invariant: operational scripts that call `startRun()` without explicitly registering the adapter will fail at runtime when domain code emits pokes.

Found two categories of evidence:

1. **Closed within scope**: Package boundary is clean (verified by grep), dependency direction one-way, read side properly isolated in api, interface exports correct.

2. **Broken**: Scripts like `trigger-cold-start-committed.ts` and potentially others in ops/qa directories enqueue workflows without registering `ReplicachePokeAdapter`. When workflow execution reaches `emitReplicachePokes()`, the triggers port throws because adapter is null. This breaks the invariant that "all code paths must register first."

The composition wrapper provides graceful degradation but is easy to miss; operational scripts bypass it by not importing the wrapper. Triggers layer enforces immediately (throws on null) with no fallback.

Documented as must-fix with remediation: audit all operational scripts for registration and add the call where missing.
